# Показатели ASC

Разбирайте **официальные данные пользователя из App Store Connect**, загруженные в Appeeky: точное число загрузок, доход, покупки внутри приложения, подписки и пробные сроки. Это собственные данные приложения, а не оценки.

## Что нужно заранее

- Учётная запись Appeeky с подключённым ASC: Settings → Integrations → App Store Connect.
- Тариф Indie или выше: два кредита за запрос.
- Данные обновляются каждую ночь; доступна история не более чем за 90 дней.

Если ASC не подключён, предложите пользователю сделать это на [appeeky.com/settings](https://appeeky.com) и завершите работу.

## С чего начать

1. Найдите `app-marketing-context.md` и прочитайте сведения о приложении.
2. Спросите, **что нужно изучить**: загрузки, доход, подписки, страны или смену показателей со временем.
3. Спросите, **за какой срок** нужны данные; по умолчанию — последние 30 дней.
4. Уточните, нужно **одно приложение или все**.

## Получение данных

### Шаг 1 — список доступных приложений

```bash
GET /v1/connect/metrics/apps
```

Если `app_apple_id` ещё неизвестен, найдите по списку приложение пользователя.

### Шаг 2 — общий обзор всех приложений

```bash
GET /v1/connect/metrics?from=YYYY-MM-DD&to=YYYY-MM-DD
```

### Шаг 3 — данные одного приложения

```bash
GET /v1/connect/metrics/apps/:appId?from=YYYY-MM-DD&to=YYYY-MM-DD
```

Ответ содержит `daily[]`, `countries[]` и `totals`.

Полное описание API: [appeeky-connect.md](../../tools/integrations/appeeky-connect.md).

## Схемы разбора

### Сравнение двух сроков

Возьмите два отрезка равной длины и сравните:

| Показатель | Прошлый срок | Текущий срок | Смена |
|------------|--------------|--------------|-------|
| Загрузки | [N] | [N] | [+/-X%] |
| Доход | $[N] | $[N] | [+/-X%] |
| Подписки | [N] | [N] | [+/-X%] |
| Пробные сроки | [N] | [N] | [+/-X%] |
| Переход с пробы на подписку | [X]% | [X]% | [+/-X п. п.] |

**На что смотреть:**
- Загрузки растут, а доход стоит на месте → возможная причина в цене или экране оплаты.
- Пробных сроков больше, но переходов на подписку столько же → проверьте экран оплаты или первые шаги пользователя.
- Доход растёт при том же числе загрузок → платная часть стала работать лучше.

### Ежедневный ход

По `daily[]` найдите:
- **Всплески:** могли ли их вызвать новая функция, обновление или публикация в прессе?
- **Спады:** совпали ли они с обновлением, сменой сезона или правил поиска?
- **Общее направление:** сравните скользящее среднее за семь дней с прошлыми семью днями.

### Разбор по странам

Отсортируйте `countries[]` по загрузкам и доходу:
1. **Пять стран с наибольшим числом загрузок:** вложены ли силы в ASO для этих рынков?
2. **Пять стран с наибольшим доходом:** высокий ARPD (средний доход с загрузки) — повод уделить им больше сил в ASO.
3. **Много загрузок, мало дохода:** там слабо работает платная часть.
4. **Мало загрузок, много дохода:** перспективный рынок; стоит перевести приложение.

### Проверка качества дохода

Посчитайте по данным:

| Показатель | Формула | Ориентир |
|------------|---------|----------|
| ARPD | Доход / Загрузки | Более $0.05 — хорошо; более $0.20 — отлично |
| Доля пробных сроков | Пробные сроки / Загрузки | Более 20% — многие доходят до экрана оплаты |
| Переход на подписку | Подписки / Пробные сроки | Более 25% — хороший результат |
| Доход с подписки | Доход / Подписки | Зависит от цены |

## Вид ответа

### Сводка по приложению

```
📊 [Название приложения] — [срок]

Загрузки:       [N]  ([+/-X%] к прошлому сроку)
Доход:          $[N] ([+/-X%])
Подписки:       [N]  ([+/-X%])
Пробные сроки:  [N]  ([+/-X%])
Число покупок:  [N]  ([+/-X%])
Проба→подписка: [X]%

Главные рынки по загрузкам:
  1. [Страна] — [N] загрузок, $[N]
  2. [Страна] — [N] загрузок, $[N]
  3. [Страна] — [N] загрузок, $[N]

Главные выводы:
- [Что значит общий ход]
- [Необычный скачок и его возможная причина]
- [Найденный шанс для роста]

Что сделать:
1. [Точное действие по данным]
2. [Точное действие по данным]
```

### Оповещение о смене показателей

Если показатель изменился больше чем на 20%, выделите это:

```
⚠️  Загрузки на этой неделе упали на [X]%
    Возможные причины: [2–3 версии]
    Дальше: [точные шаги для проверки]
```

## Частые вопросы

**«Почему упали загрузки?»**
1. Получите данные по дням и найдите начало спада.
2. Проверьте, не вышло ли в этот день обновление.
3. Проверьте места по ключевым словам с помощью `keyword-research`.
4. Проверьте действия соперников с помощью `competitor-analysis`.

**«Для каких стран стоит сделать перевод?»**
Возьмите данные по странам → отсортируйте по загрузкам → найдите рынки с большим числом загрузок, где язык не английский → примените навык `localization`.

**«Платная часть стала работать лучше?»**
Сравните долю пробных сроков и переходов с пробы на подписку за два срока → для улучшения экрана оплаты примените `monetization-strategy`.

## Связанные навыки

- `app-analytics` — настройка всей аналитики и выбор главных показателей.
- `monetization-strategy` — рост переходов на подписку и улучшение экрана оплаты.
- `retention-optimization` — снижение оттока с опорой на эти данные.
- `localization` — выход на лучшие рынки по данным о странах.
- `ua-campaign` — проверка того, виден ли прирост платных установок в скачке загрузок.
