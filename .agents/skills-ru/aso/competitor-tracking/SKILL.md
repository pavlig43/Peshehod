# Слежение за соперниками

Настройте и ведите постоянный учёт перемен у соперников: новых данных страницы, сдвигов по запросам, падения оценок и новых функций. Замечайте их до того, как они повлияют на места вашего приложения.

## Разовый разбор и постоянное слежение

| | Навык `competitor-analysis` | Этот навык (`competitor-tracking`) |
|---|---|---|
| **Частота** | Один подробный разбор | Раз в неделю или месяц |
| **Итог** | План действий | Список перемен и оповещения |
| **Главный вопрос** | Пробелы и место на рынке | Что изменилось и почему это важно |
| **Данные** | Один снимок | Разница между «до» и «после» |

## Подготовка: составьте список для слежения

1. Найдите `app-marketing-context.md`.
2. Спросите, **кто три-пять главных соперников**; по возможности возьмите их App ID.
3. Спросите, **как часто нужен обзор**; советуйте раз в неделю.
4. Спросите, **что тревожит больше всего**: запросы, оценки, картинки или цены.

Если соперники неизвестны, найдите их через Appeeky:

```bash
GET /v1/keywords/ranks?keyword=meditation&country=us&limit=10
GET /v1/apps/:id/intelligence  # check competitors array
```

## За чем следить

### Данные страницы

Проверяйте каждую неделю через Appeeky:

```bash
GET /v1/apps/:id  # title, subtitle, description
```

Замечайте:
- **Смену названия:** новое ключевое слово или новое место на рынке.
- **Смену подзаголовка:** проба нового обещания или поисковых слов.
- **Смену описания:** иной способ объяснять пользу, особенно в Google Play.
- **Новые снимки экрана:** смена стиля или внедрение лучшего варианта после проверки.

### Места по ключевым словам

```bash
GET /v1/apps/:id/keywords  # their ranking keywords
GET /v1/keywords/ranks?keyword=[shared keyword]  # who's ranking where
```

Замечайте:
- слова, по которым соперник только начал находиться: он улучшил страницу под них; стоит ли вам тоже?
- слова, по которым соперник перестал находиться: это шанс;
- обгон вашего приложения по общему запросу.

### Оценки и отзывы

```bash
GET /v1/apps/:id/reviews?sort=recent&limit=20
GET /v1/apps/:id  # current rating
```

Замечайте:
- падение оценки: возможно, вышло плохое обновление; можно показать устойчивость своего приложения;
- всплеск отзывов с одной звездой на одну тему: задачу пользователей, которую вы можете решить;
- новые хорошие отзывы о функции, которой у вас нет.

### Места в чартах

```bash
GET /v1/market/movers?genre=[genre_id]&country=us
GET /v1/categories/:id/top?country=us&limit=25
```

Замечайте:
- вход соперника в первую десятку категории или выход из неё;
- нового соперника, который резко поднялся в чарте.

### Цена и экран оплаты

Раз в 4–6 недель проверяйте вручную:
- смену длины пробного срока;
- смену цены: снижение может означать ставку на быстрый рост, повышение — работу над доходом за всё время жизни пользователя;
- новый вид экрана оплаты или новые планы.

## Образец еженедельного отчёта

Проводите такой разбор каждый понедельник:

```
Итоги по соперникам — неделя от [даты]

Приложения: [список]

НАЙДЕННЫЕ ПЕРЕМЕНЫ:
━━━━━━━━━━━━━━━━━
[Имя соперника]
  Данные страницы: [сменились / без перемен]
    → [что именно сменилось]
  Главные запросы: [прибавил X / потерял Y / без перемен]
  Оценка: [X.X → X.X] ([+/-N] оценок за неделю)
  Место в чарте: [№ N → № N в категории]
  Тема новых отзывов: [если заметная]

[Повторите для каждого соперника]

ШАНСЫ:
1. [Соперник X потерял место по слову Y — можно нацелиться на него]
2. [У соперника X много жалоб на Z — это ваша сильная сторона]
3. [Соперник X поднял цену — можно показать свою выгоду]

УГРОЗЫ:
1. [Соперник X теперь третий по запросу; вы — восьмой]
2. [Появился новичок: [имя] — проверьте его страницу]

ДЕЛА:
1. [Точный ответ на перемену]
2. [Запрос, на который стоит нацелиться из-за пробела соперника]
```

## Когда нужен полный разбор за месяц

Запускайте полный `competitor-analysis`, если:
- соперник поднялся в чарте категории больше чем на десять мест;
- соперник сменил название — признак крупной смены места на рынке;
- новый соперник вошёл в первую десятку категории;
- ваше место упало по запросу, на который недавно нацелился соперник.

## Как повторять проверку

### Вручную — совет для небольшой команды

Поставьте напоминание в календаре. Запускайте запросы Appeeky выше и заполняйте образец отчёта.

### С частью работы по расписанию

Можно написать скрипт, который раз в неделю обращается к Appeeky и сравнивает результаты:

```bash
#!/bin/bash
APPS=("6759740679" "987654321" "111222333")
KEY="apk_your_key"

for APP_ID in "${APPS[@]}"; do
  echo "=== $APP_ID ==="
  curl -s "https://api.appeeky.com/v1/apps/$APP_ID" \
    -H "X-API-Key: $KEY" | jq '.data | {title, subtitle, rating, reviewCount}'
done
```

Храните результаты каждой недели и сравнивайте с предыдущими.

### Appeeky MCP в Claude/Cursor

Каждый понедельник просите агента:

```
«Проверь приложения [ID1], [ID2], [ID3] и сравни их данные
страницы и главные поисковые слова с прошлой неделей».
```

Агент соберёт отчёт через `get_app`, `get_app_keywords` и `get_app_reviews`.

## Как отвечать на действия соперника

| Перемена | Ваш ответ |
|----------|-----------|
| Соперник добавил ваш главный запрос в название | Защитите место: проверьте свои данные страницы и при нужде поднимите ставку ASA |
| Соперник отказался от общего запроса | Шанс: уделите запросу больше сил и поднимите ставку ASA |
| Соперник улучшил снимки экрана | Проверьте свои: остались ли они лучшими в категории? |
| Оценка соперника упала ниже 4,0 | Пока разница заметна, упомяните свою оценку в рекламном тексте |
| Соперник выпустил новую функцию | Внесите в план продукта; пока выделяйте свои отличия |
| Новый соперник вошёл в первую десятку | Проведите для него полный `competitor-analysis` |

## Связанные навыки

- `competitor-analysis` — разовая глубокая стратегия по соперникам.
- `keyword-research` — работа с найденными пробелами по запросам.
- `market-movers` — отслеживание соперников по всему чарту.
- `apple-search-ads` — ответ на шаги соперника ставками ASA.
- `aso-audit` — проверка своей страницы после поиска пробелов.
