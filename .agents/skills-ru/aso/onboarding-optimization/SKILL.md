# Первые шаги в приложении

Улучшайте первый запуск, чтобы больше людей выполнили главное действие и получили пользу — этот момент помогает предсказать, останутся ли они надолго.

## Что считать первой пользой

**Первая польза — не регистрация.** Это первый случай, когда человек правда получил пользу от приложения. Сначала найдите именно его.

| Тип приложения | Первое полезное действие |
|----------------|--------------------------|
| Фитнес | Закончена первая тренировка |
| Работа и дела | Создана первая задача или проект |
| Общение | Добавлен первый знакомый или опубликован материал |
| Финансы | Подключён первый счёт или задан бюджет |
| Игры | Пройден первый уровень или матч |
| Медитация | Закончено первое занятие |
| Фото и видео | Отредактировано или сохранено первое фото |

**Правило:** все первые шаги должны как можно скорее вести к одному этому действию.

## С чего начать

1. Найдите `app-marketing-context.md`.
2. Спросите: **какое действие даёт первую пользу?**
3. Уточните, **какая доля новичков делает его за сутки**: это отправная точка.
4. Узнайте, **где люди уходят**: на каком шаге, если это известно.
5. Спросите, **сколько длятся первые шаги сейчас**: экраны и время.
6. Узнайте, **настроен ли путь пользователя в Firebase или Mixpanel**.

## Схема проверки первых шагов

### Шаг 1. Запишите нынешний путь

Перечислите все экраны от запуска до первого полезного действия:

```
Запуск → [экран 1] → [экран 2] → ... → первая польза
```

Каждому экрану дайте метку: **обязателен**, **даёт пользу** или **лишь мешает**.

Всё, что лишь мешает, уберите или отложите.

### Шаг 2. Оцените каждый экран

| Признак | Вопрос | Оценка |
|---------|--------|--------|
| **Нужен ли** | Можно ли получить первую пользу без него? | 0 — пропустить |
| **Время** | Подходящий ли сейчас момент для этого запроса? | |
| **Польза взамен** | Понимает ли человек, зачем ему это? | |
| **Трудность выбора** | Сколько решений он должен принять? | |

### Шаг 3. Выберите время для просьбы о разрешении

Просьбы о доступе — главная точка ухода. Правила:

| Доступ | Когда просить | Когда не просить |
|--------|--------------|-----------------|
| Push-уведомления | После первой пользы | Сразу при запуске |
| Место | Когда оно нужно функции | При регистрации |
| Камера и микрофон | При первом применении | До любой пользы |
| Контакты | Когда человек открыл функцию общения | На вводных экранах |
| Отслеживание (ATT) | Когда человек уже вложил время в приложение | При первом запуске |

**Экран перед системным запросом:** сперва покажите пояснение в стиле родного интерфейса. Люди, которые понимают зачем нужен доступ, разрешают его в 2–3 раза чаще.

### Шаг 4. Упростите регистрацию

| Устройство пути | Влияние | Совет |
|----------------|---------|-------|
| Регистрация до первой пользы обязательна | Много уходов | Отложить до первого полезного действия |
| Только почта и пароль | Умеренно много уходов | Добавить «Вход с Apple» и Google |
| Длинная настройка профиля | Много уходов | Задать не больше одного вопроса, остальное отложить |
| Нужна проверка почты | Тормозит начало | Отложить или сделать необязательной |

**Гостевой режим, чтобы попробовать до регистрации:** дайте людям получить главную пользу до создания учётной записи. Переход гостей к регистрации обычно составляет 40–60%, а при жёстком входе в начале — 15–30%.

## Схемы по типу приложения

### Сперва польза — совет для большинства

```
Запуск → показ главной функции или проба с действием
       → первая польза
       → «Сохраните свой результат» → регистрация
       → просьбы о доступе
       → подстройка под человека
```

### Сперва подстройка — для здоровья, фитнеса и ИИ

```
Запуск → 3–5 вопросов о человеке с полосой хода
       → «Ваш план готов» — показ итога
       → регистрация, когда человек уже вложил время
       → первое полезное действие
```

### Сперва общение — для соцсетей

```
Запуск → вход через Apple/Google одним нажатием
       → поиск друзей и советы, на кого подписаться
       → первая лента с материалами
       → первое полезное действие: запись, ответ или реакция
```

## Ориентиры пути

| Шаг | Хорошо | Плохо |
|-----|--------|-------|
| Запуск → первое действие | Более 85% | Менее 70% |
| Переход к регистрации | Более 60% | Менее 40% |
| Разрешение на push | Более 50% | Менее 30% |
| Первая польза в день установки | Более 40% | Менее 20% |
| Вернулись на следующий день | Более 30% | Менее 15% |

## Вопросы для подстройки

Если в начале нужна подстройка под человека:
- задайте не больше **3–5 вопросов**;
- каждый ответ должен заметно менять дальнейший опыт;
- показывайте ход, например «Шаг 1 из 3»;
- давайте выбирать картинкой или кнопкой, а не печатать текст;
- не спрашивайте сведения, которые не примените сразу.

## Место экрана оплаты в первых шагах

**Правило:** сначала покажите пользу, потом цену.

| Место | Когда работает |
|-------|----------------|
| До первой пользы | Почти никогда: человек ещё не знает ценности |
| Сразу после первой пользы | Хорошо: человек только что ощутил итог |
| На следующий день | Лучше всего для приложений с подпиской |
| При открытии платной функции | Хорошо, когда платность связана с отдельной функцией |

Детали экрана оплаты см. в `monetization-strategy`.

## Вид ответа

### Проверка первых шагов

```
Нынешний путь:
  [Экран 1] — нужен / мешает
  [Экран 2] — даёт пользу
  [Экран 3] — нужен / мешает
  ...
  [Первое полезное действие] — шаг N

Где уходят:
  Наибольший уход: [экран] ([X]% выходов, если известно)
  Возможная причина: [версия]

Советы:
1. [Убрать или отложить X] — возможный итог: [рост доли первой пользы]
2. [Поставить Y перед Z] — почему это поможет: [довод]
3. [Добавить пояснение перед запросом доступа Z] — итог: [рост доли согласий]

Новый путь:
  Запуск → [экран] → [экран] → первая польза → регистрация → доступы
  Убрано шагов: [N]
  Время до первой пользы: [X с → X с]
```

### Образец текста перед запросом доступа

```
[Значок нужного доступа]

[Заголовок о пользе]
Например: «Узнавайте, когда ваша цель достигнута»

[Пояснение одной строкой]
Например: «Мы пришлём лишь те напоминания, которые вы сами задали».

[Разрешить]     [Не сейчас]
```

## Связанные навыки

- `ab-test-store-listing` — проверка разных первых шагов.
- `app-analytics` — запись пути к первой пользе.
- `rating-prompt-strategy` — время просьбы оценить после первой пользы.
