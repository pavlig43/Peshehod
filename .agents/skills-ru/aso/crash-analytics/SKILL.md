# Анализ сбоев

Помогайте разбирать сбои по важности, устранять их и понимать, как они влияют на видимость приложения в App Store и его оценки.

## Почему сбои важны для ASO

- **Место в App Store:** алгоритм Apple понижает приложения с частыми сбоями.
- **Подборки App Store:** высокий уровень сбоев мешает попасть в выбор редакции.
- **Оценки:** сбои — главная причина отзывов с одной звездой.
- **Удержание:** сбой в первом сеансе резко снижает долю людей, вернувшихся на следующий день.

**Цель:** более 99,5% сеансов без сбоев и более 99% пользователей без сбоев.

## Средства

| Средство | Что даёт | Настройка |
|----------|----------|-----------|
| **Firebase Crashlytics** | Сбои и ANR почти сразу, стеки с именами функций | Добавьте `FirebaseCrashlytics` через CocoaPods или SPM |
| **App Store Connect** | Ход частоты сбоев, сбои на сеанс | Уже есть, код не нужен |
| **Xcode Organizer** | Общие журналы сбоев из TestFlight и App Store | Xcode → Window → Organizer → Crashes |
| **MetricKit** | Сведения с устройства: зависания и время запуска | iOS 13+, работает само |

**Совет:** сочетайте Crashlytics для быстрых оповещений и поиска с App Store Connect для проверки общего хода.

## Настройка Crashlytics

### iOS (Swift)

```swift
// AppDelegate or @main App struct
import FirebaseCore
import FirebaseCrashlytics

@main
struct MyApp: App {
    init() {
        FirebaseApp.configure()
        // Crashlytics is auto-initialized
    }
}
```

### Ошибки без сбоя приложения

```swift
// Log a non-fatal error
Crashlytics.crashlytics().record(error: error)

// Log a custom key for debugging context
Crashlytics.crashlytics().setCustomValue(userId, forKey: "user_id")
Crashlytics.crashlytics().setCustomValue(screenName, forKey: "current_screen")
```

### Android (Kotlin)

```kotlin
// build.gradle (app)
implementation("com.google.firebase:firebase-crashlytics:18.x.x")

// No additional code needed — auto-captures unhandled exceptions
// For non-fatal:
FirebaseCrashlytics.getInstance().recordException(throwable)
```

## Как расставить срочность

Не все сбои одинаково вредны. Ставьте их в очередь по влиянию:

**Оценка важности = Частота сбоя × Число затронутых людей × Вес группы пользователей.**

| Уровень | Признаки | Когда чинить |
|---------|----------|-------------|
| P0 — критичный | Сбой при запуске, оплате или главном действии; более 1% сеансов | Сегодня |
| P1 — высокий | Сбой на частом пути; более 0,1% сеансов | В этом выпуске |
| P2 — средний | Сбой в редком случае; менее 0,1% сеансов | В следующем выпуске |
| P3 — низкий | Очень редкий сбой, который не мешает работе; менее 0,01% сеансов | В список будущих дел |

### Разбор панели Crashlytics

1. Сортируйте по **Impact** — числу разных затронутых людей, а не по общему числу сбоев.
2. Разбейте по местам: `onboarding`, `checkout`, `core feature`, `background`, `launch`.
3. Назначьте P0 или P1 для трёх-пяти главных проблем.
4. Включите в Crashlytics **оповещение о быстром росте**, если проблема затронет более 0,5% людей.

## Как читать отчёт о сбое

```
Fatal Exception: com.example.NullPointerException
  at com.example.UserProfileVC.loadData:87
  at com.example.HomeVC.viewDidLoad:45

Keys:
  user_id: 12345
  current_screen: "home"
  app_version: "2.3.1"
  os_version: "iOS 17.3"
```

**Шаги поиска причины:**
1. Откройте файл и строку в Xcode: `UserProfileVC.swift:87`.
2. Проверьте, что здесь может быть `nil`.
3. Повторите ошибку с теми же данными: версией ОС, устройством и экраном.
4. До исправления напишите проверку, на которой ошибка проявится.

## Расшифровка стека

Crashlytics сам подставляет имена функций, если загружены файлы dSYM. Если в стеке нет имён:

```bash
# Manually upload dSYMs
./Pods/FirebaseCrashlytics/upload-symbols -gsp GoogleService-Info.plist -p ios MyApp.app.dSYM
```

Для сборок с Bitcode скачайте dSYM через App Store Connect → Activity → Build → dSYMs.

## Данные о сбоях в App Store Connect

- **App Store Connect → App Analytics → Crashes** — ход частоты сбоев по версиям.
- Сравнивайте частоту до и после каждого выпуска.
- Скачок в одной версии указывает на ошибку, внесённую в ней.

**Формула частоты сбоев:** Сбои / Сеансы × 100.

## Выпуск с малым риском

Выпускайте приложение по этапам, чтобы заметить сбои до полного охвата.

**iOS:** App Store Connect → Version → Phased Release; выход за семь дней: 1% → 2% → 5% → 10% → 20% → 50% → 100%.

**Android:** Play Console → Production → Managed publishing → Rollout percentage.

**Правило:** следите за Crashlytics 24 часа на каждом этапе. Если частота сбоев вырастет более чем на 0,2%, остановите выпуск.

## Ответы на отзывы с одной звездой из-за сбоев

1. Найдите версию приложения, после которой появились такие отзывы.
2. Исправьте сбой.
3. Ответьте на каждый отзыв: «Исправлено в версии X.X — обновите приложение».
4. После выхода правки примените `rating-prompt-strategy`, чтобы вернуть оценку.

### Отчёт об устойчивости

```

Уровень P0 (чинить сразу):
  № 1 [вид ошибки] — [X] людей, [X]% сеансов
      Файл: [имя:строка]
      Причина: [версия причины]

  № 2 [вид ошибки] — [X] людей, [X]% сеансов

План:
  Сегодня:  исправить P0 № 1 → выпустить срочную правку
  Неделя:   исправить P1 № 2 и № 3 → включить в v[X.X]

```

## Связанные навыки

- `app-analytics` — вся аналитика приложения, где Crashlytics — одна часть.
- `rating-prompt-strategy` — вернуть оценку после устранения сбоев.
- `review-management` — отвечать на отзывы о сбоях.
- `retention-optimization` — сбои в первый день вредят удержанию.
- `app-store-featured` — частота сбоев выше 2% мешает попасть в подборки редакции.
