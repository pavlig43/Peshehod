# Когда просить оценку приложения

Подбирайте время, способ и круг людей для просьбы оценить приложение, чтобы получать больше высоких оценок и меньше низких. Оценки влияют на место в App Store и на решение поставить приложение с его страницы.

## Почему оценки важны для ASO

- **Поиск:** приложения с высокой оценкой лучше стоят по запросам, где много соперников.
- **Установки:** звёзды видны в поиске; 4,8 сразу выглядит лучше, чем 4,2.
- **iOS:** оценку можно сбросить для новой версии через App Store Connect.
- **Android:** оценки копятся постоянно, поэтому после плохого срока восстановиться трудно.

## Главное правило

**Просите оценку только после того, как человек получил пользу.** Слишком ранняя просьба ведёт к низким звёздам. Просьба после удачного действия — к оценкам 4–5.

## iOS — SKStoreReviewRequest

Родной запрос Apple. Правила:
- Показывается не больше **трёх раз в год**, сколько бы раз вы ни вызывали его.
- Apple сама решает, показывать ли окно; вызов этого не обещает.
- Не просите оценку после ошибки, сбоя или неприятного действия.
- Вид окна изменить нельзя.

```swift
import StoreKit

// Call at the right moment
if let scene = UIApplication.shared.connectedScenes.first as? UIWindowScene {
    SKStoreReviewController.requestReview(in: scene)
}
```

## Android — Play In-App Review API

Родной запрос Google. Правила:
- Жёсткого предела нет, но при частых вызовах Google сокращает показы.
- Показывайте после явно удачного действия.
- Нельзя узнать, поставил ли человек оценку: это защищено ради его частной жизни.

```kotlin
val manager = ReviewManagerFactory.create(context)
val request = manager.requestReviewFlow()
request.addOnCompleteListener { task ->
    if (task.isSuccessful) {
        val reviewInfo = task.result
        val flow = manager.launchReviewFlow(activity, reviewInfo)
        flow.addOnCompleteListener { /* proceed */ }
    }
}
```

## Как выбрать момент

### После удачного действия

Найдите в приложении от одного до трёх действий, после которых люди особенно довольны:

| Тип приложения | Удачный момент | Плохой момент |
|----------------|----------------|--------------|
| Фитнес | После законченной тренировки | После пропуска занятия |
| Работа и дела | После завершения проекта или задачи | После ошибки сохранения или обмена данными |
| Игры | После победы на уровне или над сильным врагом | После поражения |
| Финансы | После первой удачной операции | После непонятной ошибки |
| Медитация | После полного занятия | Сразу при запуске |
| Покупки | После удачной оплаты или доставки | После ошибки при оплате |

### Правила по сеансам

Просите оценку лишь у людей, которые отвечают всем условиям:

```
Условия показа:
✓ Не меньше трёх сеансов — это не первый вход
✓ После установки прошло хотя бы три дня
✓ Главное полезное действие выполнено хотя бы раз
✓ В прошлом сеансе не было сбоя
✓ В этом сеансе не было ошибки, отмены или другого плохого сигнала
✓ Для этой версии оценка ещё не поставлена
```

## Короткий вопрос до родного окна — совет

До вызова окна магазина покажите один вопрос в приложении:

```
«Нравится ли вам [название приложения]?»
  [Да, очень!]   [Не очень]
```

- **«Да»** → вызовите `SKStoreReviewRequest` или Play In-App Review.
- **«Не очень»** → покажите форму для замечаний по почте или в приложении, **не** вызывайте родное окно.

Так недовольные люди не попадут сразу в окно оценки на одну-две звезды.

**Ожидаемый эффект:** с таким отбором средняя оценка может вырасти на 0,3–0,8 звезды.

## Сброс оценок для новой версии iOS

iOS позволяет сбросить оценки при новой версии в App Store Connect. Делайте это осмысленно:

- **Сбросьте после крупной правки**, если устранены главные жалобы.
- **Не сбрасывайте** после спорной перемены, которая не понравилась людям.
- После сброса часто, но с отбором, просите оценки в первые семь дней.
- Начните с самых вовлечённых людей: тех, кто давно и часто пользуется приложением.

## Как восстановить оценку после падения

### Найдите причину

1. Сопоставьте падение с датами выпуска и найдите версию, после которой оно началось.
2. Прочитайте отзывы с одной звездой за этот срок и найдите общую жалобу.
3. Исправьте проблему в следующем выпуске.
4. Ответьте на каждый отзыв с 1–3 звёздами; см. `review-management`.

### План восстановления

После выхода правки:
1. Ответьте на плохие отзывы: «Исправлено в версии X.X — обновите приложение и сообщите, всё ли в порядке».
2. Часть людей изменит свою оценку после ответа.
3. Попросите оценить самых верных пользователей с наибольшим числом сеансов.
4. Не просите людей, которые уже оставили плохой отзыв.

### Сроки

```
День 0:   Причина найдена — готовится срочная правка
Дни 1–3: Ответить на каждый плохой отзыв и признать проблему
День 7:  Выпустить правку и ответить прежним авторам: «Исправлено в X.X»
День 8+: Просить оценку после пяти сеансов, если семь дней не было сбоев
Неделя 3: Следить за оценкой — рост на 0,2–0,5 звезды за 2–4 недели
```

## Как часто просить оценку

| Платформа | Предел | Совет |
|-----------|--------|-------|
| iOS | Три раза за 365 дней — предел Apple | Один-два раза на версию |
| Android | Жёсткого предела нет, но Google сокращает показы | Раз в 30 дней на человека |

Не показывайте просьбу дважды за один сеанс.

## Вид ответа

### План по оценкам

```
Оценка сейчас: [X.X] ★ ([N] оценок)
Платформа: iOS / Android / обе

Подходящие моменты:
1. [Имя события] — когда [условие]
2. [Имя события] — когда [условие]

Вопрос до родного окна: да / нет
  Если да: «Нравится ли вам [название]?» → Да / Не очень

Правила показа:
  Сеансов не меньше [N]
  После установки прошло не меньше [N] дней
  За последние [N] сеансов не было сбоя
  Главное полезное действие выполнено: да
  Для этой версии оценка уже поставлена: нет

Ожидаемый итог: +[X] звезды за [N] недель

План возврата оценки, если она ниже 4,0:
  1. [Правка] — выпустить к [дате]
  2. [План ответов] — ответить на [N] отзывов
  3. [Просьба оценить] — начать [дата], группа [кого просить]
```
