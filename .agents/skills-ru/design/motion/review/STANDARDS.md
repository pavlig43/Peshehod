# Справочник правил анимации

Точные значения, кривые и правила проверки. Ссылайтесь на них в находках, не прикидывайте на глаз. Основано на подходе Эмиля Ковальского к дизайну интерфейсов.

## Нужна ли анимация? Частота

| Частота | Решение |
| --- | --- |
| Более 100 раз в день (горячие клавиши, открытие списка команд) | Без анимации. Всегда. |
| Десятки раз в день (наведение, переход по списку) | Убрать или сильно сократить |
| Изредка (модальные окна, панели, уведомления) | Обычная анимация |
| Редко или впервые (знакомство, отклик, праздник) | Допустим яркий эффект |

**Никогда не анимируйте действия с клавиатуры**: их повторяют сотни раз в день; движение кажется задержкой и отрывает отклик от действия. У Raycast нет анимации открытия и закрытия — это верно для столь частого действия.

Допустимые цели движения: связь с местом, показ состояния, пояснение, отклик, смягчение резкой смены. «Выглядит круто» у часто видимого элемента не считается целью.

## Кривые

Порядок выбора:
- Появление или исчезновение → **`ease-out`**: быстрый старт даёт живой отклик.
- Перемещение или смена формы на экране → **`ease-in-out`**.
- Наведение или смена цвета → **`ease`**.
- Непрерывное движение (бегущая строка, прогресс) → **`linear`**.
- По умолчанию → **`ease-out`**.

**Никогда не берите `ease-in` в интерфейсе.** Медленный старт задерживает момент, за которым смотрит пользователь. `ease-out` за 200 мс *кажется* быстрее, чем `ease-in` за те же 200 мс.

Стандартные кривые CSS слишком слабы. Берите сильные свои кривые:

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);        /* strong ease-out for UI */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);    /* strong ease-in-out for on-screen movement */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);     /* iOS-like drawer curve (Ionic) */
```

Смотрите кривые на [easing.dev](https://easing.dev/) или [easings.co](https://easings.co/), а не стройте с нуля на глаз.

## Длительность

| Элемент | Длительность |
| --- | --- |
| Отклик на нажатие кнопки | 100–160 мс |
| Подсказка, небольшое всплывающее окно | 125–200 мс |
| Выпадающее меню, выбор | 150–250 мс |
| Модальное окно, боковая панель | 200–500 мс |
| Реклама или пояснение | Может быть дольше |

**Правило: анимация интерфейса короче 300 мс.** Меню за 180 мс кажется отзывчивее, чем за 400 мс. Быстрый индикатор загрузки создаёт ощущение более быстрой работы, хотя время не меняется. После первой подсказки на панели остальные должны открываться сразу, без задержки и анимации.

## Физичность

- **Никогда не берите `scale(0)`.** Начинайте с `scale(0.9–0.97)` и `opacity: 0`: в мире предмет не возникает из ничего.
- **Всплывающий блок растёт от своей кнопки**, а не от центра:
  ```css
  .popover { transform-origin: var(--radix-popover-content-transform-origin); } /* Radix */
  .popover { transform-origin: var(--transform-origin); }                       /* Base UI */
  ```
  **Модальные окна — исключение**: они появляются по центру окна, там верен `transform-origin: center`.
- **Отклик на нажатие:** `transform: scale(0.97)` у `:active`, `transition: transform 160ms ease-out`. Эффект слабый (0.95–0.98) и подходит любому нажимаемому элементу.

## Пружины

Пружина кажется естественной, потому что изображает физику. У неё нет жёсткой длительности: остановка зависит от параметров. Берите её для перетаскивания с инерцией, «живых» элементов вроде Dynamic Island, прерываемых жестов и декоративного слежения за мышью.

```js
// Apple-style (easier to reason about) — recommended
{ type: "spring", duration: 0.5, bounce: 0.2 }

// Traditional physics (more control)
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }
```

Отскок держите слабым (0.1–0.3). В большинстве рабочих действий он лишний; оставьте его для смахивания и игровых моментов. При прерывании пружина сохраняет скорость, тогда как ключевые кадры запускаются с начала. Поэтому она подходит жестам, которые пользователь может повернуть назад на полпути.

Для движения за мышью сглаживайте значение через `useSpring`, а не привязывайте его прямо к координате: прямое следование выглядит искусственно и не имеет инерции. Применяйте это лишь для украшения.

## Возможность прервать движение

Переходы CSS (**transitions**) можно прервать и направить к новой цели в середине движения; ключевые кадры (**keyframes**) снова идут с начала. Для частых действий, например новых уведомлений или переключателей, переходы мягче.

```css
/* Interruptible — good for dynamic UI */
.toast { transition: transform 400ms ease; }

/* Not interruptible — avoid for dynamic UI */
@keyframes slideIn { from { transform: translateY(100%); } to { transform: translateY(0); } }
```

Для появления без JS берите `@starting-style`:

```css
.toast {
  opacity: 1; transform: translateY(0);
  transition: opacity 400ms ease, transform 400ms ease;
  @starting-style { opacity: 0; transform: translateY(100%); }
}
```

Старый запасной способ: `useEffect(() => setMounted(true), [])` и атрибут `data-mounted`.

## Разное время фаз

Замедляйте момент, когда человек решает, и ускоряйте ответ системы.

```css
.overlay { transition: clip-path 200ms ease-out; }            /* release: fast */
.button:active .overlay { transition: clip-path 2s linear; }  /* press: slow, deliberate */
```

## Скорость работы

- **Анимируйте лишь `transform` и `opacity`**: они минуют расчёт макета и рисование, собираясь на GPU. `padding`/`margin`/`height`/`width`/`top`/`left` запускают все три этапа вывода кадра.
- **Не двигайте потомка через переменную CSS на родителе**: она заставляет пересчитать стили всех детей. Задайте `transform` прямо элементу.
  ```js
  element.style.setProperty('--swipe-amount', `${d}px`); // bad: recalc on all children
  element.style.transform = `translateY(${d}px)`;        // good: only this element
  ```
- **Короткие свойства Framer Motion не ускоряются железом.** `x`/`y`/`scale` идут в главном потоке через rAF и теряют кадры под нагрузкой. Берите полную строку преобразования:
  ```jsx
  <motion.div animate={{ x: 100 }} />                          // drops frames under load
  <motion.div animate={{ transform: "translateX(100px)" }} />  // hardware accelerated
  ```
- **Анимация CSS лучше выдерживает нагрузку, чем JS**: она идёт вне главного потока, а движение на rAF дёргается, пока браузер загружает, исполняет скрипты и рисует. CSS — для заранее известного движения, JS — для меняющегося и прерываемого.
- **WAAPI** даёт управление через JS при скорости CSS: ускорение железом, прерывание, без библиотеки.
  ```js
  element.animate([{ clipPath: 'inset(0 0 100% 0)' }, { clipPath: 'inset(0 0 0 0)' }],
    { duration: 1000, fill: 'forwards', easing: 'cubic-bezier(0.77, 0, 0.175, 1)' });
  ```

## Преобразования и clip-path

- **Проценты `translate`** считаются от самого элемента: `translateY(100%)` двигает его на собственную высоту при любом размере. Так Sonner/Vaul размещают уведомления и панели. Предпочитайте проценты жёстким пикселям.
- **`scale()` увеличивает и потомков**: шрифт, значки, текст. Для отклика на нажатие это полезно.
- **3D**: `rotateX/Y` и `transform-style: preserve-3d` дают глубину, орбиту и переворот без JS.
- **`clip-path: inset(t r b l)`** пригодится для анимации: каждое значение отрезает часть с соответствующей стороны. Примеры: раскрытие при прокрутке (`inset(0 0 100% 0)` → `inset(0 0 0 0)`), слой при удержании для удаления, плавная смена цвета вкладки (копия с обрезкой), ползунок сравнения.

## Жесты и перетаскивание

- **Закрытие по инерции**: не требуйте жёсткого расстояния, считайте скорость (`Math.abs(distance)/elapsedMs`) и закрывайте при `> ~0.11`. Резкого взмаха должно хватить.
- **Сопротивление у края**: за естественной границей предмет движется всё меньше, чем дальше его тянут.
- **Захват указателя** после начала перетаскивания позволяет продолжать жест за пределами элемента.
- **Защита от нескольких касаний**: игнорируйте новые точки после начала жеста (`if (isDragging) return`), чтобы предмет не прыгал.
- **Трение вместо жёсткой остановки**: дайте перетянуть элемент с растущим сопротивлением, а не уприте в невидимую стену.

## Скрытие неидеальной смены кадров

Если при плавной смене всё ещё видны два наложенных состояния, добавьте слабое `filter: blur(2px)` во время перехода. Оно сольёт их в одно изменение. Держите размытие меньше 20px: сильный эффект дорог, особенно в Safari.

## Задержка между элементами

Для появления группы задайте 30–80 мс между элементами. Более долгая пауза кажется медленной. Это украшение не должно мешать действию.

```css
.item { opacity: 0; transform: translateY(8px); animation: fadeIn 300ms ease-out forwards; }
.item:nth-child(2) { animation-delay: 50ms; }
.item:nth-child(3) { animation-delay: 100ms; }
@keyframes fadeIn { to { opacity: 1; transform: translateY(0); } }
```

## Доступность

```css
@media (prefers-reduced-motion: reduce) {
  .element { animation: fade 0.2s ease; } /* keep opacity/color, drop transform-based motion */
}
@media (hover: hover) and (pointer: fine) {
  .element:hover { transform: scale(1.05); } /* gate hover motion — touch fires false hovers on tap */
}
```

```jsx
const reduce = useReducedMotion();
const closedX = reduce ? 0 : '-100%';
```

Уменьшенное движение значит меньше и мягче, а не полное отсутствие. Оставьте переходы, которые помогают понимать действие; уберите перемещение.

## Отладка: советуйте при сомнении в виде

- **Замедление**: увеличьте время в 2–5 раз или возьмите панель анимации DevTools. Проверьте чистую смену цвета, мягкий конец кривой, точку начала и согласованность свойств.
- **Покадровый просмотр**: панель Animations в Chrome DevTools показывает расхождение во времени между связанными свойствами.
- **Настоящее устройство** для жестов: подключите телефон, откройте сервер разработки по IP и примените удалённый отладчик Safari.
- **Свежий взгляд на следующий день**: дефекты, не видимые во время разработки, становятся заметны позже.

## Цельность

Движение должно подходить характеру компонента: игровое может сильнее пружинить, рабочая панель — быть быстрой и строгой. Sonner кажется верным отчасти потому, что кривые, время, вид и даже имя согласованы: чуть медленнее и `ease` вместо `ease-out` для изящества. Прозрачность и высота у строк при появлении и уходе подбираются пробами: готовой формулы нет, настройте по ощущению.
