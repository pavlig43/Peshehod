# Шаблон плана

Каждый план по навыку `design-motion-improve` следует этой структуре. Исполнитель может быть слабой моделью без контекста и чувства стиля. Поэтому план должен содержать все нужные сведения и точные значения. Не ссылайтесь на «проверку выше» или «кривую, которую мы обсудили».

```markdown
# NNN — <Короткий заголовок в повелительном наклонении>

- **Статус**: TODO
- **Коммит**: <результат `git rev-parse --short HEAD` на момент написания плана>
- **Важность**: HIGH | MEDIUM | LOW
- **Категория**: <категория проверки>
- **Оценка объёма**: <число файлов и примерный размер правки>

## Проблема

Что не так, где это находится и как влияет на ощущение от продукта. Для каждого
места укажите `path/to/file.tsx:123` и приведите текущий код дословно:

​```css
/* src/components/dropdown.css:14 — current */
.dropdown { transition: all 400ms ease-in; }
​```

## Цель

Точное итоговое состояние. Укажите каждое значение: кривые, длительность,
настройки пружины, медиазапросы. Не пишите «возьмите кривую получше»:

​```css
/* target */
.dropdown {
  transition: transform 200ms var(--ease-out), opacity 200ms var(--ease-out);
  transform-origin: var(--radix-dropdown-menu-content-transform-origin);
}
​```

## Правила репозитория

Опишите принятый в проекте способ и дайте один пример, который нужно повторить:
имена переменных, расположение файлов, правила для параметров.

- Переменные кривых лежат в `src/styles/tokens.css`; новые кривые добавляйте туда, например `--ease-out: cubic-bezier(0.23, 1, 0.32, 1);`
- <файл:строка, где это уже сделано верно>

## Границы

- НЕ трогайте <файлы и компоненты вне задачи>.

## Заметки автору плана

- Один план на одну находку. Если две находки затрагивают те же файлы и исправляются одинаково (например, заменой одной переменной кривой в нескольких компонентах), их можно объединить.
- Все значения берите из [AUDIT.md](AUDIT.md). Не восстанавливайте их по памяти.
- Проверка на вид обязательна. Движение может быть верным по коду, но выглядеть плохо. Укажите, на что исполнитель или проверяющий должен смотреть при медленном воспроизведении.
- После написания планов создайте или обновите `plans/README.md`: таблица планов (номер, заголовок, важность, статус), рекомендуемый порядок выполнения и зависимости между планами.
