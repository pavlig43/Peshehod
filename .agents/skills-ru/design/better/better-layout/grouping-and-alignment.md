# Группы и выравнивание

Отступы, формы, общие края и порядок показывают, что связано между собой и что важнее.

## Объединяйте отступами, а не линиями

Есть три способа показать группу, в порядке предпочтения:

1. **Пустое место** — основной способ. Связанные элементы стоят близко, разные группы — дальше друг от друга.
2. **Фоновая форма** — карточка или залитый блок, когда группу нужно видеть как одно целое: строку выбора или перетаскиваемую карточку.
3. **Линия-разделитель** — крайний случай для плотных данных, где отступы заняли бы много места: таблиц и длинных списков настроек.

Правило структуры: отступ между группами должен быть хотя бы вдвое больше, чем внутри группы. Если элементы внутри стоят через `8px`, между группами нужно не меньше `16px`. Иначе взгляд не видит, где кончается одна группа.

```css
/* Good: spacing alone communicates the grouping */
.field-group { display: flex; flex-direction: column; gap: 8px; }
.form { display: flex; flex-direction: column; gap: 24px; }

/* Bad: uniform spacing plus lines to compensate */
.form > * { margin-bottom: 12px; border-bottom: 1px solid var(--separator); }
```

```html
<!-- Good: Tailwind -->
<div class="space-y-6">
  <div class="space-y-2">…field group…</div>
  <div class="space-y-2">…field group…</div>
</div>
```

Если разделитель всё же нужен, пусть он будет тонким и малоконтрастным. Не ставьте его рядом с большим отступом: отступ уже отделил группы.

## Отличайте элементы управления от текста

По виду должно быть ясно, что с элементом можно работать: фон, рамка, подчёркивание или постоянное место для действий, например панель инструментов или нижняя строка. Если действие выглядит как обычный текст, его не заметят.

```html
<!-- Bad: action looks exactly like the description text next to it -->
<p class="text-zinc-600">Your trial ends soon. Upgrade now</p>

<!-- Good: the action reads as an action -->
<p class="text-zinc-600">Your trial ends soon.</p>
<button class="font-medium text-blue-600">Upgrade now</button>
```

Верно и обратное: не оформляйте простой текст как кнопку. Если на метку нельзя нажать, а она выглядит как соседние кнопки, пользователи будут нажимать на неё зря.

## Выравнивайте по общим краям

Выберите немного опорных линий и выровняйте всё по ним. Взгляд идёт вдоль ровного края, когда человек просматривает текст.

- Любой лишний сдвиг — значок на `2px` дальше текста или карточка с иным внутренним отступом — создаёт зрительный шум, даже если трудно сказать почему.
- Для ступеней вложенности возьмите один шаг отступов проекта. Если шкалы ещё нет, подойдёт `16px`; при глубокой вложенности повторяйте тот же шаг.
- Числа в таблицах выравнивайте по конечному краю строки (о цифрах равной ширины см. `design-better-typography`), текст — по начальному.

```css
/* Good: one shared leading edge, one indent step */
.section { padding-inline: 24px; }
.section .child { margin-inline-start: 16px; }

/* Bad: three unrelated leading edges in one column */
.header { padding-inline-start: 20px; }
.list-item { padding-inline-start: 14px; }
.footer { padding-inline-start: 24px; }
```

## Логические свойства вместо физических

Для положения, зависящего от направления письма, задавайте начальный и конечный край. Тогда при `dir="rtl"` расположение отразится само:

| Физическое свойство (не брать) | Логическое свойство (брать) |
| --- | --- |
| `margin-left` | `margin-inline-start` |
| `padding-right` | `padding-inline-end` |
| `left: 0` | `inset-inline-start: 0` |
| `text-align: left` | `text-align: start` |
| `border-right` | `border-inline-end` |

```html
<!-- Good: Tailwind logical utilities -->
<div class="ms-4 pe-6 text-start">…</div>

<!-- Bad: breaks in RTL -->
<div class="ml-4 pr-6 text-left">…</div>
```

Физические свойства оставляйте лишь там, где речь именно о стороне экрана вне зависимости от языка: например, элемент должен быть привязан к вырезу устройства или к физическому направлению жеста.

Если порядок элементов показывает ход процесса — звёзды оценки, шаги, полоса прогресса, — в RTL он меняется зеркально: звёзды заполняются с конечного края. Flexbox и grid с логическими свойствами отражаются сами, элементы с ручными координатами — нет. Порядок цифр внутри числа не меняется. Это и другие правила двунаправленного текста описаны в навыке `design-better-typography`.

## Порядок по важности

Люди читают сверху вниз и от начального края строки к конечному. Располагайте текст так же:

- Самое важное — ближе к верху и начальному краю. Чем ниже и дальше элемент, тем меньше на него смотрят.
- Дайте главному место. Не прячьте число, за которым пришёл пользователь, под второстепенными строками. Уберите детали в свёрнутые блоки, вкладки или отдельные экраны.
- В строке первым идёт то, по чему её узнают: имя или заголовок. Метаданные и действия — следом.

```html
<!-- Good: primary fact first, detail demoted -->
<div>
  <p class="text-2xl font-semibold">$4,320.00</p>
  <p class="text-sm text-zinc-500">Available balance</p>
</div>

<!-- Bad: the key fact is buried below the fold of the card -->
<div>
  <p class="text-sm">Account 4402 · Opened 2019 · Standard tier</p>
  <p class="text-sm">Last statement: June 30</p>
  <p class="text-sm">Balance: $4,320.00</p>
</div>
```

Думайте о **начальном и конечном крае**, а не о левом и правом. Вместе с логическими свойствами это сохранит тот же порядок важности в RTL.

## Не перегружайте первый экран

Первый экран — оглавление, а не вся книга. Если выделено всё, не выделено ничего:

- Одно главное действие на экран (как цвет помогает в этом, см. `design-better-colors`).
- Когда второстепенных действий больше двух-трёх, уберите их в меню.
- Лучше короткий экран со ссылками на детали, чем длинный экран, где сразу видно всё.
