# Отступы и гибкость макета

Расстояние между кнопками, поля у края экрана, подсказки о скрытом тексте и макет, который выдерживает смену размера и языка.

## Дайте соседним целям место

Слишком близкие кнопки часто нажимают по ошибке и видят как одно целое. Если в проекте нет шкалы плотности, начните с этих значений:

| Между чем | Начальное значение |
| --- | --- |
| Соседние кнопки и поля с рамкой или заливкой | `12px` |
| Кнопки без рамки: текст и значки | `24px` |
| Несвязанные группы элементов | От `24px` (вдвое больше отступа внутри группы) |

Кнопкам без рамки нужно больше места, потому что границу между ними создаёт сам отступ. В плотных рабочих интерфейсах отступы могут быть меньше, если области нажатия не пересекаются и их легко различать. Не растягивайте уже удобный макет лишь ради этих чисел.

```html
<!-- Good: bordered buttons at 12px, icon buttons given room -->
<div class="flex gap-3">
  <button class="rounded-lg border px-4 py-2">Cancel</button>
  <button class="rounded-lg bg-blue-600 px-4 py-2 text-white">Save</button>
</div>

<!-- Bad: three borderless icon buttons packed at 4px -->
<div class="flex gap-1">
  <button><TrashIcon /></button>
  <button><ArchiveIcon /></button>
  <button><ShareIcon /></button>
</div>
```

Требования WCAG к размеру цели, более удобные размеры и расширение области через псевдоэлементы описаны в навыке `design-better-accessibility`. Эти отступы нужны сверх того, чтобы области нажатия не накладывались друг на друга.

## Отступайте кнопками от края

В макете с текстом кнопка вплотную к краю окна может выглядеть как часть системы и обрезаться у скруглённых углов или зоны жестов. Оставляйте её внутри полей макета. Действие от края до края уместно, если это осознанная часть интерфейса приложения или платформы и учтены безопасные зоны:

```css
/* Good: inset action bar */
.action-bar {
  padding-inline: 16px;
  padding-bottom: calc(16px + env(safe-area-inset-bottom));
}
.action-bar button { width: 100%; border-radius: 12px; }

/* Bad: button glued to all three edges */
.action-bar button {
  width: 100vw;
  border-radius: 0;
  position: fixed;
  bottom: 0;
}
```

Если в проекте нет переменной отступа, на телефоне начните примерно с `16px` по бокам. Внутри этих полей кнопка всё ещё может занять всю ширину текста.

## Подсказывайте о скрытом содержимом

Скрывать сложные детали полезно, но без подсказки о них никто не узнает. У содержимого за пределами экрана или в свёрнутом блоке должен быть видимый знак. Сохраняйте принятые в продукте индикаторы прокрутки и раскрытия. Если их нет, подойдут такие приёмы:

- **Видна часть следующего элемента.** В горизонтальной ленте или карусели оставьте `16–32px` следующей карточки у края. Если ряд кончается ровно по краю, он выглядит законченным и его не прокручивают.
- **Кнопка раскрытия.** У свёрнутого блока должна быть стрелка или кнопка «Показать ещё». Подпись говорит, что скрыто: «Показать ещё 12 результатов», а не просто «Ещё».
- **Знак обрезки.** У сокращённого текста должны быть многоточие и способ раскрыть его. Как обрезать текст, описано в `design-better-typography`.

В ленте часть следующей карточки показывается за счёт внутреннего отступа контейнера, а точки прилипания остаются у края текста.

```css
.scroller {
  display: flex;
  gap: 12px;
  overflow-x: auto;
  padding-inline: 24px;
  scroll-padding-inline: 24px;
  scroll-snap-type: x mandatory;
}
.scroller > * {
  flex: 0 0 calc(100% - 48px - 24px); /* container minus margins minus peek */
  scroll-snap-align: start;
}
```

```html
<!-- Tailwind: the 80% width keeps the next card's leading 16-32px visible -->
<div class="flex gap-3 overflow-x-auto px-6 [scroll-padding-inline:1.5rem] snap-x snap-mandatory">
  <div class="w-[80%] shrink-0 snap-start">…</div>
  <div class="w-[80%] shrink-0 snap-start">…</div>
</div>
```

## Фон до краёв, кнопки внутри

У края экрана два слоя ведут себя по-разному:

- **Слой содержимого**: фон, крупные изображения и прокручиваемые списки доходят до краёв окна.
- **Слой управления**: текст и кнопки остаются внутри полей макета и безопасных зон поверх содержимого.

```css
/* Good: full-bleed media inside a constrained article */
.article {
  display: grid;
  grid-template-columns: 1fr min(65ch, calc(100% - 48px)) 1fr;
}
.article > * { grid-column: 2; }
.article > .full-bleed { grid-column: 1 / -1; }
```

Закреплённые шапки и плавающие кнопки учитывают безопасные зоны:

```css
.fab {
  position: fixed;
  inset-inline-end: calc(16px + env(safe-area-inset-right));
  bottom: calc(16px + env(safe-area-inset-bottom));
}
```

## Сохраняйте структуру, пока она помещается

Порог смены макета зависит от содержимого, а не от списка устройств:

- Меняйте макет там, где он на деле перестаёт помещаться: боковая панель слишком сжимает текст или колонки карточек становятся слишком узкими. Не выбирайте `768px` лишь потому, что так задано в шаблоне.
- Сворачивайте поздно. Пока широкий макет помещается, он остаётся привычным и устойчивым. Раннее сворачивание зря отнимает место.
- Для компонентов предпочитайте **запросы к контейнеру**: карточка должна подстраиваться под свою колонку, а не под всё окно.

```css
/* Good: component adapts to its container */
.card-list { container-type: inline-size; }
@container (max-width: 400px) {
  .card { grid-template-columns: 1fr; }
}

/* Bad: viewport media query breaks the card inside a narrow sidebar */
@media (max-width: 768px) {
  .card { grid-template-columns: 1fr; }
}
```

Сначала проверьте самый узкий и самый широкий размер из поддерживаемых: они чаще ломаются. Затем — промежуточные.

## Учитывайте рост и обрезку текста

Макет ломается с двух сторон: текст растёт, окно сужается.

**Рост строки зависит от языка и длины исходного текста.** Одного процента на все случаи нет. Правила:

- Не задавайте ширину по английской подписи. Берите `max-width` и перенос строк.
- Не задавайте фиксированную высоту блоку текста. Если нужен нижний предел, берите `min-height`.
- Ширину кнопки задаёт её подпись вместе с `padding-inline`, а не жёсткое число.
- Перед выпуском проверьте макет на псевдопереводе или языке с длинными строками.

```css
/* Good: label defines the size */
.button { padding-inline: 16px; white-space: nowrap; }

/* Bad: German will overflow or truncate */
.button { width: 96px; overflow: hidden; }
```

**Обрезка:** не ставьте важные действия там, где их может отрезать: у нижнего края панели с меняющейся высотой, ниже видимой части окна с фиксированной высотой или за появившейся клавиатурой. Главное действие держите в устойчивой части интерфейса: закреплённом подвале с безопасным отступом или вверху экрана. Если содержимое окна прокручивается, ряд кнопок не должен прокручиваться вместе с ним.
