# Детали, которые делают интерфейс приятнее

Качество интерфейса редко создаёт одна крупная вещь. Чаще его дают небольшие детали, работающие вместе. Применяйте эти правила при создании и проверке кода интерфейса.

При проверке замедлите интерфейс: запустите движение со скоростью 10% в панели Animations браузера и пройдите все состояния — наведение, фокус, нажатие, загрузку, пустой экран. То, что явно не так на 10%, слегка мешает и на полной скорости.

Сохраняйте библиотеку компонентов, переменные и плотность проекта. Следуйте принятому языку движения, кроме случаев, где правило ниже задаёт точный способ действия.

Шрифты, перенос, цифры равной ширины и отступы текста описаны в `design-better-typography`; размеры областей нажатия, фокус, клавиатура, ARIA и уменьшенное движение — в `design-better-accessibility`; группы, отступы между блоками, пороги смены макета и RTL — в `design-better-layout`.

## Основные правила

### 1. Соосные скругления

Внешний радиус = внутренний радиус + отступ. Несогласованные радиусы вложенных элементов — частая причина, по которой интерфейс кажется неаккуратным.

### 2. Зрительное выравнивание важнее геометрического

Если точный геометрический центр выглядит неверно, поправьте на глаз. Кнопкам со значками, треугольнику воспроизведения и несимметричным значкам часто нужна ручная поправка.

### 3. Тени для высоты, рамки для структуры

Если рамка кнопки, карточки или блока нужна лишь для глубины, лучше взять несколько прозрачных слоёв `box-shadow`. Рамки, которые показывают структуру или состояние, сохраняйте: разделители, границы блоков, выбранный элемент и фокус.

### 4. Прерываемое движение

Для смены состояния при действиях берите переходы CSS: их можно прервать на полпути. Ключевые кадры оставьте для заранее заданной последовательности, которая проходит один раз.

### 5. Делите появление и добавляйте задержку

Для редкого появления, где порядок помогает показать иерархию, делите содержимое на смысловые части и запускайте их с паузой около 100 мс, а не анимируйте один общий блок. Не вводите задержку для частых действий.

### 6. Мягкий уход

При уходе берите небольшой фиксированный `translateY`, а не сдвиг на всю высоту. Уход мягче появления. Для обоих переходов берите `ease-out`.

### 7. Движение значков по ситуации

Состояния значка меняйте через `opacity`, `scale` и `blur`, а не мгновенным скрытием. Берите именно эти значения: масштаб от `0.25` до `1`, прозрачность от `0` до `1`, размытие от `4px` до `0px`. Если в `package.json` есть `motion` или `framer-motion`, используйте путь импорта этого пакета (если есть оба — принятый рядом) и `transition: { type: "spring", duration: 0.3, bounce: 0 }`; отскок всегда `0`. Если библиотеки движения нет, держите оба значка в DOM (один с абсолютным положением) и плавно меняйте прозрачность через CSS с `cubic-bezier(0.2, 0, 0, 1)`. Так появление и уход работают без новой зависимости.

### 8. Обводка изображений

Для ровной глубины добавьте изображениям тонкую обводку `1px` с малой непрозрачностью. В светлой теме цвет — чистый чёрный (`oklch(0 0 0 / 0.1)`), в тёмной — чистый белый (`oklch(1 0 0 / 0.1)`). Не берите почти чёрный из slate, zinc или другого окрашенного нейтрального тона: такая обводка подхватывает цвет фона и выглядит как грязь на краю.

### 9. Сжатие при нажатии

Слабый `scale(0.96)` даёт кнопке ощутимый отклик. Берите всегда `0.96`. Не опускайтесь ниже `0.95`: эффект кажется преувеличенным. Добавьте параметр `static`, который отключает движение там, где оно мешает.

### 10. Не анимируйте первый показ страницы

Поставьте `initial={false}` в `AnimatePresence`, чтобы при первой отрисовке не запускалось появление. Проверьте, что осознанные вступительные эффекты не сломались.

### 11. Не берите `transition: all`

Всегда называйте точные свойства: `transition-property: scale, opacity`. Класс Tailwind `transition-transform` охватывает `transform, translate, scale, rotate`.

### 12. Берите `will-change` редко

Лишь для `transform`, `opacity`, `filter` — свойств, которые GPU может собрать отдельно. Никогда не берите `will-change: all`. Добавляйте только если заметили рывок на первом кадре.

### 13. Толщина значка соответствует тексту

Значок рядом с текстом должен иметь сходный зрительный вес: штрих `1.5px` рядом с обычным текстом (400), `2px` рядом с полужирным (600). Один вес штриха для набора значков; не смешивайте библиотеки на одной поверхности.

### 14. Один SVG, цвета по состояниям

Значки берут `currentColor`, а наведение, выбор и недоступность получают через цвет и прозрачность CSS, не через отдельные файлы. По умолчанию берите контур; заливка отмечает активное состояние.

### 15. Сдерживайте движение

Не делайте свою анимацию для частых действий: она отнимает внимание при каждом повторе. Движение никогда не должно быть единственным сигналом. У каждой смены состояния нужен и неподвижный признак: цвет, значок или подпись.

## Частые ошибки

| Ошибка | Правка |
| --- | --- |
| У тесно вложенных блоков один радиус | Считайте `outerRadius = innerRadius + padding` |
| Значки выглядят смещёнными | Поправьте зрительно отступом или сам SVG |
| Рамка нужна лишь для высоты | Берите прозрачные слои `box-shadow`; структурные и смысловые рамки оставьте |
| Резкое появление по шагам или уход без связи с местом | Для редкого появления дайте задержку между элементами, уход сделайте мягче |
| Значок состояния или переключатель анимирует начальное состояние при загрузке | Добавьте `initial={false}` в нужный `AnimatePresence`; осознанные вступительные эффекты сохраните |
| `transition: all` | Назовите точные свойства |
| Рывок первого кадра | При нужде добавьте `will-change: transform` |
| Тонкий значок рядом с жирным текстом | Подберите толщину штриха к весу текста |
| Отдельный файл значка на каждое состояние | Один SVG с `currentColor`, состояния через CSS |
| Все значки с заливкой | Контур по умолчанию, заливка лишь для активного |
| Появление при каждом наведении или нажатии клавиши | Мгновенный отклик или переход цвета/прозрачности не дольше 150 мс |

## Формат отчёта о проверке

Берите этот формат лишь по просьбе об отдельной проверке зрительной доводки интерфейса. Если проверкой управляет `design-better-interface`, передайте ему факты и находки по своей теме. Его формат, шкала важности, правила объединения, предел числа находок и итог имеют приоритет.

Разделите отдельную проверку на две части.

### Находки

Сгруппируйте подтверждённые находки по правилам. Используйте таблицу Markdown с колонками **Важность**, **Место**, **Было**, **Стало**, **Почему**. Не пишите отдельные строки «Было:» и «Стало:».

- **Важность**: `HIGH` — действие вводит в заблуждение, не даёт отклика или постоянно мешает; `MEDIUM` — заметная ошибка вида или цельности; `LOW` — отдельная мелкая доводка.
- **Место**: укажите `path/to/file:line`. Если у объекта нет исходных файлов, укажите точный экран и компонент.
- **Было / Стало**: покажите текущий код и точную замену.
- **Почему**: назовите нарушенное правило и его влияние на интерфейс.

Повторяющуюся системную ошибку объедините в одну строку и перечислите все места. Правила без находок опустите.

### Пример

#### Соосные скругления
| Важность | Место | Было | Стало | Почему |
| --- | --- | --- | --- | --- |
| LOW | `src/Card.tsx:28` | `rounded-xl` у карточки и `rounded-xl` у внутренней кнопки (`p-2`) | `rounded-2xl` у карточки (`8 + 8 = 16`), `rounded-lg` у кнопки | Вложенные углы должны быть соосны |
| LOW | `src/card.css:11` | `border-radius: 16px` у обеих вложенных поверхностей | Снаружи `24px`, внутри `16px`, отступ `8px` | Равные радиусы визуально сжимают внутренний блок |

#### Сжатие при нажатии
| Важность | Место | Было | Стало | Почему |
| --- | --- | --- | --- | --- |
| LOW | `src/Button.tsx:19` | `<button className="...">` | Добавить `active:scale-[0.96] transition-transform` | Отклик на нажатие делает кнопку живой |
| MEDIUM | `src/button.css:24` | `scale(0.9)` при нажатии | Заменить на `scale(0.96)` | Ниже `0.95` эффект преувеличен |

### Проверки и итог

После находок:

1. **Проверки**: перечислите точные выполненные проверки и результаты. Пройдите все нужные состояния; для анимации посмотрите движение на скорости 10%. Если что-то не проверяли, скажите, что осталось.
2. **Итог**: `Block`, если осталась хотя бы одна находка `HIGH`; `Needs changes`, если остались лишь `MEDIUM` или `LOW`; `Approve`, только если править больше нечего.

Если находок нет, не показывайте таблицы. Напишите «Нет находок по виду интерфейса, требующих правки», укажите проверки и завершите итогом `Approve`.
