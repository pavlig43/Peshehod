# Смысловая разметка и ARIA

Родные HTML-элементы, главные области страницы, доступные имена и правила ARIA для своих элементов управления.

## Правила ARIA

1. Если есть родной элемент HTML с нужным смыслом и поведением, берите его, а не чужой элемент с добавленной ARIA.
2. Не меняйте родной смысл элемента без крайней нужды.
3. Каждый элемент управления с ролью ARIA должен работать с клавиатуры. Роль обещает полную модель клавиш, состояний и поведения.
4. Не ставьте `role="presentation"` или `aria-hidden="true"` на элемент с фокусом.
5. У каждого элемента управления должно быть доступное имя.

Лучше совсем без ARIA, чем с неверной ARIA: программа чтения верит заданным ролям, поэтому ложная роль хуже отсутствующей.

## Кнопка, ссылка и div

| Элемент | Для чего | Что даёт сам |
| --- | --- | --- |
| `<a href>` | Переход куда-то или смена URL | Открытие по Cmd/Ctrl или средней кнопкой, копирование ссылки через меню, запуск клавишей Enter |
| `<button>` | Действие: отправить, переключить, открыть, удалить | Фокус, запуск Enter **и** пробелом, смысл для формы |
| `<div onClick>` | Ни для чего | Нет роли, фокуса и работы с клавиатурой; программа чтения видит обычный текст |

```tsx
// Bad: invisible to keyboard and screen readers
<div onClick={openSettings}>Settings</div>

// Good: focus, Enter/Space activation, and semantics for free
<button onClick={openSettings}>Settings</button>
```

Если элемент выглядит нажимаемым, он должен отвечать на нажатие. Если он отвечает на нажатие, ему нужна настоящая роль элемента управления. Переделка ссылки в кнопку или наоборот нарушает ожидания людей. «Кнопка» для перехода должна быть оформленной ссылкой `<a>`.

Если родной элемент правда нельзя взять, придётся вручную добавить `role="button"`, `tabindex="0"`, а также обработчики Enter и пробела. Поэтому родной элемент почти всегда требует меньше кода.

## Главные области и заголовки

- Покажите один видимый главный участок `<main>`. `<header>`, `<nav>`, `<aside>` и `<footer>` становятся областями, между которыми можно быстро переходить в программе чтения.
- У нескольких областей одного вида должны быть разные имена: `<nav aria-label="Primary">` и `<nav aria-label="Breadcrumbs">`.
- Заголовки описывают свои разделы и образуют ясную структуру. Обычно берут один `<h1>` на страницу и верно вложенные уровни. Но не объявляйте отступление от этого правила отдельным нарушением WCAG без ясного вреда для навигации или понимания. Заголовки задают структуру, а не вид; оформляйте нужный уровень через CSS, не выбирайте тег по размеру.
- `<title>` отражает текущее место, начиная с самого точного: `Billing · Settings · Acme`.

## Доступные имена

Порядок старшинства: `aria-labelledby` > `aria-label` > родная подпись (`<label>`, текст элемента, `alt`) > атрибут `title`.

- Выбирайте видимый текст или `aria-labelledby` вместо `aria-label`: скрытая подпись легко расходится с видимым текстом, а средства перевода обрабатывают её не всегда верно.
- Кнопке с одним значком всегда нужно имя: `<button aria-label="Close">`, а значку — `aria-hidden="true"`.
- Видимая подпись должна входить в доступное имя (WCAG 2.5.3 Label in Name). Если на кнопке написано «Send», а `aria-label="Submit message"`, голосовая команда «нажми Send» не сработает.
- Доступное имя нужно и тогда, когда дизайн не показывает подпись.

```tsx
// Good: name from visible text, icon hidden
<button>
  <TrashIcon aria-hidden="true" /> Delete
</button>

// Good: icon-only, explicit name
<button aria-label="Delete">
  <TrashIcon aria-hidden="true" />
</button>
```

Добавляйте `translate="no"` к названиям брендов, словам кода и ID, чтобы автоматический перевод не портил их.

## Частые ошибки ARIA

| Ошибка | Почему это ошибка |
| --- | --- |
| `aria-label` у простого `<div>` или `<span>` | Большинство программ чтения не учитывают имена у элементов без роли и действия |
| `<button role="button">` | Лишняя роль, которая ничего не даёт |
| `aria-hidden="true"` на элементе с фокусом или его родителе | Tab приводит к месту, которого нет для программы чтения |
| `aria-labelledby` или `aria-describedby` с несуществующим ID | Имя или описание пропадает без сообщения об ошибке |
| `role="menu"` у списка ссылок | `menu` обещает поведение меню приложения со стрелками; для сайта нужен `<nav>` со списком |

## Выключенные элементы

Родной `disabled` даёт полное поведение платформы: убирает элемент из обхода Tab, запрещает запуск, применяет `:disabled` и не отправляет поле формы. Берите его, когда родной элемент управления правда недоступен. `aria-disabled="true"` лишь сообщает о состоянии; он не меняет фокус, действие или вид сам по себе.

- Не выключайте кнопку отправки заранее: оставьте её активной, проверяйте данные при отправке и переводите фокус на первую ошибку; см. [forms.md](forms.md).
- Берите `aria-disabled="true"`, если элемент намеренно должен оставаться доступным через Tab, либо если свой элемент управления не умеет использовать родной `disabled`.
- При `aria-disabled="true"` запретите запуск мышью и клавиатурой в обработчике, при нужде остановите отправку формы, добавьте явный вид выключенного состояния, включая режим принудительных цветов, и рядом объясните, почему действие недоступно.
- Не ставьте `disabled` и `aria-disabled` на один элемент вместе.
- К выключенным элементам не применяются нижние пороги контраста, но всё же оставляйте их читаемыми.
