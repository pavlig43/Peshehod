# Движение и увеличение

`prefers-reduced-motion`, увеличение страницы, перестройка макета и выбор единиц с учётом настроек пользователя.

## prefers-reduced-motion

Включайте движение лишь для тех, кто не попросил его сократить: оберните анимации в `@media (prefers-reduced-motion: no-preference)`. Тогда люди с режимом уменьшенного движения сразу увидят неподвижный вариант, и вам не придётся отменять каждую анимацию отдельно.

```css
/* Good: motion is opt-in */
.card {
  /* static styles */
}
@media (prefers-reduced-motion: no-preference) {
  .card {
    transition: transform 200ms ease-out;
  }
}
```

```tsx
// Tailwind: motion-safe / motion-reduce variants
<div className="motion-safe:transition-transform motion-safe:hover:-translate-y-1" />
```

Если в готовом проекте так перестроить код нельзя, запасной путь — общее отключение:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Берите `0.01ms`, а не `none`, чтобы события `animationend` и `transitionend` всё же сработали, иначе код JS, который их ждёт, может зависнуть.

### Что выключить, сократить или оставить

Уменьшенное движение не равно полному запрету: цель — убрать то, что вызывает головокружение, сохранив отклик интерфейса.

| Выключить совсем | Заменить | Оставить |
| --- | --- | --- |
| Параллакс при прокрутке | Сдвиг, рост и приближение → плавная смена прозрачности | Индикаторы загрузки и хода работы |
| Самозапуск видео и GIF, повторяющиеся украшения | Плавная прокрутка → мгновенный переход | Мгновенная смена состояния: цвет при наведении, рамка фокуса |
| Вращение и большие перемещения по экрану | Сами листающиеся карусели → запуск на паузе | Короткий отклик на действие, например нажатие кнопки |

Анимацию должно быть можно прервать, и она должна идти по действию пользователя. Ничто не должно запускаться само и отказываться остановиться. В режиме уменьшенного движения карусели стоят на паузе с самого начала.

## Самозапуск и интерфейс с таймером

Движение без запроса пользователя и элементы, которые действуют по времени:

- **Не запускайте медиа само без видимых кнопок управления** (WCAG 2.2.2). Если что-то движется, мигает или само обновляется дольше пяти секунд, нужна видимая кнопка паузы или остановки. Это касается и беззвучного видео на первом экране, которое идёт по кругу.
- **Лучше закрытие по нажатию, чем по таймеру.** Сообщения, которые пропадают сами, допустимы лишь для простых подтверждений. Сообщение с действием, ошибкой или нужными сведениями должно ждать закрытия. Если таймер обязателен, не ставьте меньше пяти секунд; при наведении или фокусе ставьте его на паузу.
- **Не показывайте важные сведения лишь на время.** Если единственная ссылка для отмены действия исчезнет вместе с сообщением, это потеря данных по таймеру.

## Увеличение и перестройка макета

- **Увеличение текста до 200%** (WCAG 1.4.4): всё содержимое и все функции должны работать. Не запрещайте увеличение через `user-scalable=no` или `maximum-scale=1`. Safari не соблюдает предел, но другие браузеры соблюдают.
- **Перестройка при ширине 320px** (WCAG 1.4.10): при увеличении до 400% в окне 1280px это равно окну 320px. Страница должна работать с одной вертикальной прокруткой. Исключение — содержимое, которому правда нужны две оси, например таблицы, карты и блоки кода; прокручивайте их внутри своего блока.

При увеличении чаще всего мешает жёсткая высота. Для блоков с текстом берите `min-height` и дайте им расти.

### rem и px

Учитывайте привычные единицы проекта. Если размеры заданы в `px` либо по готовой шкале Tailwind, придерживайтесь её; не смешивайте единицы без причины. Если выбор свободен — в новом коде или проекте, где уже взят `rem`, — помните: `rem` зависит от главного размера шрифта пользователя, а `px` нет.

| Берите `rem` | Берите `px` |
| --- | --- |
| `font-size` | Рамки и тонкие линии |
| `max-width` для текстовых блоков | Толщина и отступ рамки фокуса |
| Пороги смены макета (`@media (min-width: 48rem)`) | Мелкие детали `box-shadow` |
| Отступы, которые должны расти вместе с текстом | Украшения постоянного размера |

Особенно важны пороги смены макета. Если главный размер шрифта увеличен, запрос в `em` или `rem` включит узкий макет, когда тексту станет тесно; запрос в `px` этого не сделает.
