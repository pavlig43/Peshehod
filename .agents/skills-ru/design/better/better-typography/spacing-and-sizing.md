# Интервалы и размеры

Разумная шкала размеров и удобные интервалы помогают тексту больше, чем любые эффекты.

## Единицы

| Единица | Как работает |
| --- | --- |
| `px` | Постоянный размер |
| `em` | Зависит от размера текущего шрифта |
| `rem` | Зависит от размера шрифта на корне документа |
| `%` для `font-size` | Зависит от шрифта родителя, как `em` |

## Шкала шрифтов

Задайте для всего продукта небольшой набор размеров и отходите от него как можно реже. При росте проекта набор случайных размеров становится трудно поддерживать.

```css
:root {
  --text-sm: 0.875rem;
  --text-base: 1rem;
  --text-lg: 1.125rem;
  --text-xl: 1.5rem;
  --text-2xl: 2rem;
}
```

Можно взять готовую шкалу или создать свою. Шкала Tailwind от `text-xs` до `text-9xl`, где каждому размеру дана своя высота строки, — хороший готовый вариант.

В личном проекте обычных имён хватает, если ясно, где брать каждый размер. В команде полезнее имена по роли: `text-sm` говорит лишь о размере, а `text-body-sm` напоминает, где его применять.

Шкала по ролям связывает размер с высотой строки и весом: вместо трёх решений остаётся одно. Отправная точка для интерфейса продукта:

| Роль | Размер | Высота строки | Вес |
| --- | --- | --- | --- |
| Крупный акцент | `2.25rem` (36px) | `1.1` | `600` |
| Название | `1.5rem` (24px) | `1.2` | `600` |
| Заголовок | `1.125rem` (18px) | `1.3` | `600` |
| Основной текст | `1rem` (16px) | `1.5` | `400` |
| Мелкая подпись | `0.8125rem` (13px) | `1.4` | `400` |

Для выделения внутри одной роли поднимите вес на один шаг (`400` → `500`), а размер не меняйте.

## Порядок заголовков

Дайте каждому уровню заголовка следующую, меньшую ступень шкалы. Так порядок виден из системы, а не из случайных размеров:

```css
h1 { font-size: var(--text-2xl); }
h2 { font-size: var(--text-xl); }
h3 { font-size: var(--text-lg); }
```

В Tailwind уровню отвечает класс `text-2xl`, `text-xl` или `text-lg`. Обычно такое правило собирают в одном компоненте или `@layer base`, а не повторяют возле каждого заголовка.

При проверке страницы сравните итоговые размеры заголовков в каждом смысловом разделе. Если дочерний заголовок выглядит важнее родительского, зрительный порядок ломается. Глубокие уровни могут иметь один размер, когда удобные ступени кончились; отличайте их весом или межбуквенным интервалом. Заголовок не должен быть мельче основного текста, если это не намеренная верхняя подпись.

Смысловой порядок заголовков и качество структуры относятся к `design-better-accessibility`. Выбирайте HTML-элемент по устройству документа, а здесь задавайте ему понятный вид. Не берите уровень заголовка лишь из-за размера, который браузер даёт ему по умолчанию.

## Кернинг и расстояние между буквами

- **Кернинг** подстраивает отдельные пары вроде `AV` и `Ye`. Он задан в шрифте, и браузеры включают его сами. Выключайте его через `font-kerning: none` лишь по ясной причине.
- **`letter-spacing`** добавляет одно и то же расстояние между всеми знаками:
  - крупным заголовкам часто помогает слегка отрицательное значение;
  - мелким подписям прописными нужен небольшой положительный интервал, чтобы буквы не слипались;
  - обычному тексту не нужно ни то ни другое.

```css
/* Good */
.display-heading {
  letter-spacing: -0.02em;
}

.uppercase-label {
  text-transform: uppercase;
  letter-spacing: 0.05em;
}
```

## Высота строки

| Текст | Значение |
| --- | --- |
| Заголовки | Около `1.1` |
| Основной текст | `1.5`–`1.6` |

Берите числа без единиц: они растут вместе со шрифтом, а постоянная запись вроде `line-height: 24px` — нет. Классы Tailwind `leading-snug`, `leading-normal` и `leading-relaxed` подходят как значения по умолчанию и редко требуют правки.

Малая высота строки годится для короткого текста. Если текст переносится на три и больше строк, нужна высота хотя бы `1.4` даже в карточке или строке списка, где мало места: читать тесный абзац труднее, чем отвести под строку больше высоты.

```css
/* Bad: card description at heading leading */
.card-description { line-height: 1.1; }

/* Good: it wraps to 3 lines, so it reads as body text */
.card-description { line-height: 1.4; }
```

## Обрезка пустого места вокруг букв через text-box

Шрифты оставляют место над и под буквами, поэтому текст в кнопках и метках часто выглядит чуть опущенным. `text-box` убирает это место. У свойства две части: какой край обрезать (`trim-both`, `trim-start`, `trim-end`) и до какой линии:

| Значение | До какой линии обрезает |
| --- | --- |
| `cap` | Высота прописных букв сверху |
| `alphabetic` | Базовая линия снизу |
| `text` | Собственный край текста в шрифте, с местом для нижних частей букв |

```css
/* trim top and bottom */
.badge {
  text-box: trim-both cap alphabetic;
}

/* trim only the top */
.heading {
  text-box: trim-start cap;
}

/* trim only the bottom */
.label {
  text-box: trim-end alphabetic;
}
```

Поддержка есть в Chromium 133+ и Safari 18.2+, но пока нет в Firefox. Это необязательное улучшение: браузеры без поддержки сохранят обычные поля текста.
