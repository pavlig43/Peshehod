# Цвета OKLCH

OKLCH — цветовое пространство, близкое к зрительному восприятию: светлотой, насыщенностью и оттенком в нём удобно управлять. Применяйте его, если проект уже работает с OKLCH, если создаёте новую систему цветов или если пользователь просит перевести цвета либо собрать палитру. В остальных случаях сохраняйте принятые в проекте переменные и запись цвета. Цельная система hex или RGB лучше, чем второй формат ради одной правки. Для наглядной работы откройте [oklch.fyi](https://oklch.fyi).

## Основные правила

### 1. Берите цветовое пространство, близкое к восприятию

- **Уважайте текущую систему.** Не переводите запись цвета лишь потому, что открыт этот навык. Берите смысловые переменные и формат проекта, если задача не включает смену всей системы цветов.
- **Ровная светлота.** Одинаковые шаги L дают сходные изменения яркости. `oklch(0.5 ...)` зрительно посередине. В HSL значение `lightness: 50%` выглядит очень по-разному в зависимости от оттенка.
- **Устойчивый оттенок.** Синий HSL уходит в фиолетовый при смене светлоты. Оттенок OKLCH остаётся тем же во всей шкале.
- **Отдельная насыщенность.** C измеряет силу цвета независимо от светлоты. Насыщенность HSL так не работает.
- **Ограниченный охват.** Не каждый цвет oklch можно показать в sRGB. При некоторых оттенках сильная насыщенность обрежется, поэтому проверяйте охват.

### 2. Записывайте OKLCH единообразно

```
oklch(L C H)
oklch(L C H / alpha)
```

| Канал | Диапазон | Значение |
| --- | --- | --- |
| L (светлота) | 0–1 | 0 — чёрный, 1 — белый. Зрительно ровная шкала. |
| C (насыщенность) | 0–~0.4 | Сила цвета. 0 — серый. Предел зависит от L и H. |
| H (оттенок) | 0–360 | Угол оттенка в градусах. |
| alpha | 0–1 | Необязательная прозрачность. Запись через косую черту. |

```css
oklch(0.637 0.237 25.331)
oklch(0.8 0.05 200 / 0.5)
```

Для L и C берите три знака после точки, для H — не больше трёх. Убирайте конечные нули и пишите `0` вместо `-0`. Поддержка OKLCH входит в Baseline 2023. Если проекту нужны очень старые браузеры, проверьте список его целевых браузеров, а не полагайтесь на общий процент поддержки.

### 3. Измеряйте контраст, охват и поведение палитры

| Правило | Значение |
| --- | --- |
| Граница светлого и тёмного | L > 0.73 — светлый фон → тёмный текст; ниже светлый текст всё ещё получает более высокую оценку |
| Разница светлоты на светлом фоне | Передний план L < 0.35, если фон L > 0.9 |
| Разница светлоты на тёмном фоне | Передний план L > 0.9, если фон L < 0.25 |
| Порог ухода оттенка | Разброс > 10° между ступенями палитры заметен |
| APCA для основного текста | \|Lc\| >= 75 минимум, >= 90 лучше |
| APCA для другого текста | \|Lc\| >= 60 минимум |
| WCAG 2 для обычного текста | 4.5:1 AA, 7:1 AAA |
| Правка контраста (лишь по просьбе) | Сначала меняйте L; по возможности сохраняйте C и H, затем вновь измерьте пару на экране |

## Частые ошибки

| Ошибка | Правка |
| --- | --- |
| Цвет задан прямо, в обход смысловых переменных проекта | Возьмите или добавьте переменную нужной роли в формате проекта |
| Один цвет OKLCH добавлен в проект на hex/RGB | Сохраните принятый формат, если задача не включает переход всей системы |
| В палитре HSL оттенок уходит в сторону | Постройте шкалу с постоянным оттенком oklch |
| Контраст не проходит (проверьте передний план на его фоне через APCA) | Укажите пару, измеренное Lc и нужный порог; меняйте цвета лишь по просьбе (тогда сначала L, сохраняя C и H) |
| Сильная насыщенность без проверки охвата | Ограничьте C до максимума для данного L/H в sRGB |
| Одинаковое абсолютное C у разных оттенков | Берите одинаковый C% от максимума, чтобы сила цвета выглядела сходно |
| Цвет P3 без запасного sRGB | Добавьте вариант до `@media (color-gamut: p3)` |
| Тёмная тема получена простым обращением светлой палитры | Возьмите светлую палитру за основу, затем настройте C и L и проверьте каждую пару текста и фона |
| Hex в Tailwind v4 `@theme` | Переведите в oklch |
| Прозрачность записана через запятую | Берите косую черту: `oklch(L C H / alpha)` |
| Один оттенок значит разное (цвет ссылки взят для украшения) | Один цвет — один смысл; для второго случая возьмите нейтральный |
| Смысловая переменная взята не по своей роли (цвет разделителя для текста) | Добавьте переменную нужной роли; не заимствуйте её лишь из-за значения |
| На экране несколько цветных фонов кнопок | Заливайте цветом лишь одно главное действие; остальные держите нейтральными |
| Палитра проверена лишь в светлой теме | Проверьте каждую пару переднего плана и фона в обеих темах |

## Формат отчёта о проверке

Берите этот формат лишь по просьбе об отдельной проверке цветов. Если проверкой управляет `design-better-interface`, передайте ему факты и находки по цветам. Его формат, шкала важности, правила объединения, предел числа находок и итог имеют приоритет.

Разделите отдельную проверку на две части.

### Находки

Сгруппируйте подтверждённые находки по правилам. Используйте таблицу Markdown с колонками **Важность**, **Место**, **Было**, **Стало** и **Почему**. Не пишите отдельные строки «Было:» и «Стало:».

- **Важность**: `HIGH` — текст нельзя прочитать или смысловой цвет вводит в заблуждение; `MEDIUM` — заметная ошибка темы, охвата или единообразия; `LOW` — мелкая доводка.
- **Место**: укажите `path/to/file:line`. Если у объекта нет исходных файлов, укажите точный экран и компонент.
- **Было / Стало**: покажите текущее значение или переменную и точную замену.
- **Почему**: назовите нарушенное правило и, если нужно, приведите измерения контраста или охвата.

Повторяющуюся системную ошибку объедините в одну строку со всеми затронутыми местами. Правила без находок опустите.

| Важность | Место | Было | Стало | Почему |
| --- | --- | --- | --- | --- |
| MEDIUM | `src/theme.css:18` | `color: #3b82f6` | `color: oklch(0.623 0.188 259.815)` | В новом проекте цвета задаются переменными OKLCH |
| MEDIUM | `src/palette.ts:31` | Одно абсолютное C для разных оттенков | Одинаковый C% от максимума каждого оттенка | Одинаковое C выглядит неодинаково ярко у разных оттенков |
| HIGH | `src/theme.css:52` | Цвет P3 без запасного варианта | Добавить sRGB до `@media (color-gamut: p3)` | На экранах без P3 цвет не работает |

### Проверки и итог

После находок:

1. **Проверки**: перечислите точные выполненные проверки и результаты, включая измерение контраста, проверку охвата и обе темы, где они есть. Если что-то не проверяли, скажите, что ещё нужно проверить.
2. **Итог**: `Block`, если осталась хотя бы одна находка `HIGH`; `Needs changes`, если остались лишь `MEDIUM` или `LOW`; `Approve`, только если править больше нечего.

Если находок нет, не показывайте таблицу. Напишите «Нет находок по цветам, требующих правки», укажите проверки и завершите итогом `Approve`.
