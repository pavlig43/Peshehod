# Кому принадлежит функция Kotlin

## Главное правило

Помещайте функцию у самого узкого владельца, которому она точно соответствует по смыслу. Синтаксис расширения меняет вид вызова, но не делает получатель владельцем поведения.

По умолчанию отвергайте расширения простых, общих и библиотечных типов: они создают ложное впечатление принадлежности, засоряют предметную область, подсказки и импорты и могут привести к конфликтам имён.

## Порядок выбора

Идите по шагам.

### 1. Назовите владельца по смыслу

Назовите действие и понятие, которому оно принадлежит. Если владелец неясен, сперва выясните это, а потом выбирайте синтаксис.

### 2. Сразу отвергайте вводящий в заблуждение получатель

Для `String`, простых типов, коллекций, `Flow`, типов фреймворка и сторонних библиотек нужны **все** условия:

- Узкая, связная область видимости `private` или `internal`.
- Действие верно для любого значения получателя.
- Нет политики, состояния, ввода-вывода или зависимости.
- Вызов через получатель заметно яснее.
- Нет лучшего владельца среди типов проекта.

Если хотя бы одно условие не выполнено, расширение такого получателя запрещено: выберите иную форму на шаге 3. `private fun <T> MutableList<T>.swap(...)` может подойти: действие свойственно списку, не несёт политики и нужно лишь внутри алгоритма.

### 3. Выберите форму функции

| Смысл | Предпочтительная форма |
|---|---|
| Поведение, присущее типу проекта | Метод этого типа |
| Действие над разными типами без состояния | Функция верхнего уровня |
| Создание или разбор значения | Фабрика целевого типа или именованная функция верхнего уровня |
| Политика, состояние, ввод-вывод, часы, язык и регион либо зависимости | Сервис или иной объект, переданный как зависимость |
| Действие, свойственное типу, с более ясным вызовом через получатель и всеми условиями шага 2 | Расширение |

Сервис нужен, лишь если поведение хранит политику или состояние либо требует ввода-вывода, часов, языковых настроек или зависимостей. В остальных случаях передайте явные параметры функции без состояния.

### 4. Перенесите поведение и его вызовы

Перенесите реализацию, затем поправьте вызовы, импорты и ссылки на функцию. Сохраните или пометьте устаревшими открытые точки входа, если выпуск не задуман как ломающий совместимость. Поддержку перехода для закрытых функций добавляйте лишь при наличии конкретных пользователей.

```kotlin
// Было: String ошибочно объявлен владельцем создания UserId.
fun String.toUserId(): UserId {
    return UserId(this)
}

// Стало: создание принадлежит UserId.
@JvmInline
value class UserId private constructor(val value: String) {
    companion object {
        fun parse(raw: String): UserId {
            return UserId(raw)
        }
    }
}

val id = UserId.parse(raw)
```

### 5. Проверьте результат

Для любой формы проверьте видимость, импорты, конфликты имён и совместимость. Для расширений также проверьте получатели, допускающие `null`, обобщённые типы и приоритет будущего метода класса над расширением. Соберите проект и запустите тесты. При сбое сузьте API или вернитесь к шагу 1.

## Неверные доводы

| Довод | Ответ |
|---|---|
| «Так вызов читается плавно» | Удобный синтаксис не делает тип владельцем поведения. |
| «В Kotlin принято писать расширения» | Даже привычный приём должен верно передавать смысл. |
| «Это лишь `private` или `internal`» | Узкая область помогает, только если выполнены все условия. |
| «Класс с полезными функциями был бы хуже» | Возьмите функцию верхнего уровня или фабрику целевого типа. |
| «Политика по умолчанию очевидна» | Часовой пояс и языковые настройки — часть политики; задайте их явно. |
| «Код уже есть в запросе на слияние» | Наличие кода не доказывает верный выбор владельца. |

## Тревожные признаки

- Смысл предметной области привязан к `String`, числам, коллекциям, `Flow` или сторонним типам.
- Расширение скрывает часы, языковые настройки, ввод-вывод, политику или зависимости.

## Частые ошибки

| Ошибка | Что сделать |
|---|---|
| `Long.toDisplayDate()` | Правила часового пояса и языка должны принадлежать форматтеру. |
| Расширение скрывает разбор строки | Возьмите `Type.parse(raw)` или именованный парсер. |
| Открытое расширение библиотечного типа | Заново выберите форму по шагам 1–3. |
