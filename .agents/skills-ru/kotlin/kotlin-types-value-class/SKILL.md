# `value class` или `data class` в Kotlin

## Главное правило

Для типа с одним полем, которое несёт смысл предметной области, предпочитайте `@JvmInline value class`. Класс `data class` нужен для объединения нескольких полей.

## Как проверять

1. Найдите обёртки с одним полем, API с большим числом простых типов и обёртки `@Immutable` в состоянии интерфейса.
2. Решите, выражает ли это одно значение настоящее различие в предметной области. Если нет, оставьте простой тип или используйте псевдоним типа.
3. Проверьте, как замена повлияет на равенство, запись и чтение данных, вызов из Java и упаковку значения в часто выполняемом коде.
4. Меняйте тип лишь при ясном смысле и допустимых изменениях контракта.
5. Снова запустите нужные тесты и компиляцию; если цель — скорость Compose, вновь проверьте отчёты компилятора или измерения рекомпозиции.

## Как выбрать

| Ситуация | Что взять |
|---|---|
| Одно поле с отдельным смыслом (`UserId`, `EmailAddress`, `Percentage`) | `@JvmInline value class` |
| Одно поле без отдельного смысла, только для группировки | Псевдоним типа или сам простой тип |
| Несколько полей | `data class` |
| Нужны свои `equals`/`hashCode`, отличные от обёрнутого значения | `data class`: класс значения берёт равенство основного типа |
| Тип служит обобщённым аргументом или допускает `null` в доказанно часто выполняемом месте | `data class` или простой тип |

```kotlin
// ВЕРНО: одно поле с отдельным смыслом.
@JvmInline value class UserId(val value: String)
@JvmInline value class EmailAddress(val value: String)
@JvmInline value class Percentage(val value: Float)

// НЕВЕРНО: data class для одного поля с отдельным смыслом.
data class UserId(val value: String)

// НЕВЕРНО: value class без отдельного смысла.
@JvmInline value class Wrapper(val value: String) // Достаточно String или псевдонима типа.

// НЕВЕРНО: value class, когда нужно своё равенство.
@JvmInline value class CaseInsensitiveString(val value: String)
// Равенство value class следует равенству String, а оно учитывает регистр.
// Если нужны другие правила равенства, берите data class.
```

## Устойчивость в Compose

Если отчёт Compose указывает на обёртку с одним полем:

1. Убедитесь, что основной тип стабилен: `String`, простой или иной стабильный тип.
2. Если задача обёртки лишь в различии типов, предпочитайте класс значения аннотации `@Immutable` на обёртке.
3. Не меняйте открытый контракт или способ записи данных лишь ради чистого отчёта.

```kotlin
// Было: это простое значение легко спутать с другими строками.
data class UiState(val userId: String)

// Стало: граница Compose получает стабильный тип предметной области.
@JvmInline value class UserId(val value: String)
data class UiState(val userId: UserId)
```

## Что проверить при замене

Прежде чем заменить обёртку, проверьте видимый вызывающему коду контракт:

| Проверка | Действие |
|---|---|
| Важен формат JSON или API | Проверьте запись. `@Serializable data class A(val value: String)` записывается как объект, а класс значения — как вложенное значение. |
| Нужно своё равенство или хеширование | Оставьте `data class`: равенство класса значения повторяет основной тип. |
| Вызывающий код берёт `copy()` или разбирает объект на части | Оставьте `data class` либо осознанно обновите вызовы: у классов значения нет этих удобств. |
| Граница Java или фреймворк с активным отражением | Проверьте совместимость: Java видит основной тип, а обобщённые и `Any`-значения упаковываются. |
| Часто выполняемый код с `null`, обобщениями или `vararg` | До замены измерьте затраты на упаковку. |
| Тело конструктора, `lateinit`, делегированные свойства или поля с хранением | Оставьте `data class` либо измените устройство типа: класс значения хранит лишь значение конструктора. |

## Упаковка нескольких значений — лишь после замера

Не заменяйте понятный `data class` из нескольких полей битовой упаковкой без данных профилировщика о цене выделения памяти в часто выполняемом месте. При нужде Compose даёт `packFloats`, `packInts` и парные функции `unpack*` в `androidx.compose.ui.util`:

```kotlin
@JvmInline value class Offset(val packedValue: Long)

fun Offset(x: Float, y: Float): Offset {
    return Offset(packFloats(x, y))
}
val Offset.x: Float get() = unpackFloat1(packedValue)
val Offset.y: Float get() = unpackFloat2(packedValue)
```

## Частые ошибки

| Ошибка | Что сделать |
|---|---|
| `data class` с одним полем предметной области | Заменить на `@JvmInline value class` |
| Класс значения без особого смысла, лишь обёртка | Взять псевдоним или простой тип |
| Классу значения нужно своё равенство | Взять `data class` |
| Класс значения — обобщённый аргумент в часто выполняемом коде | Измерить цену упаковки; при значимом вреде оставить простой тип или `data class` |
| `@Immutable` на типе, который мог бы быть классом значения | Если основной тип стабилен, взять класс значения |
| Забыли `@JvmInline` | Для класса значения с одним полем всегда ставить `@JvmInline` |

## Тревожные признаки

- У `data class` ровно одно свойство.
- `String`, `Long` или `Int` стоят там, где разные значения нельзя путать, например в `fun transfer(from: String, to: String, amount: Long)`.
- `@Immutable` стоит на обёртке с одним полем.
- Псевдоним типа применён для настоящего различия предметной области: псевдонимы не создают новый тип во время работы и не защищают от подмены.

## Когда не применять

- Нужно несколько полей — берите `data class`.
- Нужны свои `equals`/`hashCode` — берите `data class`.
- Тип часто используется с `null` или как обобщённый в важном для скорости коде — сперва измерьте цену упаковки.
- Проекту не нужно различать типы — хватит псевдонима или простого типа.
- Замена незаметно изменит JSON, вызов из Java, отражение или поведение фреймворка.
