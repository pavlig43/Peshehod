# Службы

Hindsight состоит из трёх служб. В зависимости от задачи их можно запускать вместе или по отдельности.

## Служба API

Основной движок памяти. Выполняет все операции с памятью:

- **Retain**: принимает данные, извлекает факты, строит граф знаний
- **Recall**: ищет по смыслу среди воспоминаний
- **Reflect**: создаёт ответ с учётом черт поведения

```bash
hindsight-api        # Default port: 8888
```

Служба API не хранит состояние и может работать на нескольких узлах за балансировщиком нагрузки. Все данные хранятся в PostgreSQL.

По умолчанию API также сам выполняет фоновые задачи (обобщение ментальных моделей). При высокой нагрузке эту работу можно отключить в API и передать отдельным обработчикам.

## Служба обработчиков

Отдельная служба для фоновых задач. Она берёт **тот же пакет и образ Docker**, что и API, но запускается через другую точку входа.

```bash
hindsight-worker     # Default metrics port: 8889
```

Обработчики берут задачи из PostgreSQL, время от времени проверяя очередь. Несколько обработчиков могут работать одновременно без конфликтов.

| Развёртывание | Встроенный обработчик | Отдельные обработчики |
|------------|-----------------|-------------------|
| **Разработка** | ✅ Просто, всё в одном | ❌ Излишне |
| **Небольшая рабочая среда** | ✅ Меньше служб | ❌ Излишне |
| **Высокая нагрузка** | ❌ API станет узким местом | ✅ Можно масштабировать отдельно |
| **Долгие задачи** | ❌ Занимают ресурсы API | ✅ Выполняются отдельно |

Чтобы запустить отдельные обработчики, отключите встроенный в API и запустите нужное число процессов:

```bash
# Disable internal worker in API
HINDSIGHT_API_WORKER_ENABLED=false hindsight-api

# Start dedicated workers (run multiple instances)
hindsight-worker --worker-id worker-1
hindsight-worker --worker-id worker-2
```

У каждого обработчика есть адреса `/health` и `/metrics` для слежения за работой.

Перед сокращением числа обработчиков или их удалением освободите задачи командой `hindsight-admin decommission-worker <worker-id>`.

Все настройки приведены в разделе [«Настройка — распределённые обработчики»](./configuration#distributed-workers), а запуск в Kubernetes — в разделе [«Установка — Helm»](./installation#distributed-workers).

## Панель управления

Веб-интерфейс для управления банками памяти и их изучения:

- Просмотр агентов и банков памяти
- Изучение сущностей и связей
- Просмотр истории загрузки данных и операций
- Проверка запросов recall в диалоге

Панель подключается к службе API и даёт наглядный интерфейс для разработки и поиска ошибок.

При запуске на собственном сервере панель можно поднять отдельно через npx. Подробности — в разделе [«Установка — собственный сервер»](./installation#control-plane).
