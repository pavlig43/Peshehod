# RAG и память

Обычный RAG (генерация с поиском данных) находит документы, похожие на запрос. Hindsight даёт структурную память: учитывает время, распознаёт сущности и строит представления о мире.

## Сравнение возможностей

| Возможность | RAG | Hindsight |
|------------|-----|-----------|
| **Способ поиска** | Только сходство по смыслу | По смыслу, ключевым словам, графу и времени |
| **Вывод через несколько связей** | Ограничен найденными фрагментами | Переходы по графу связей между сущностями |
| **Запросы о времени** | Совпадение ключевых слов (например, «весна») | Разбор дат и отбор по диапазону |
| **Понимание сущностей** | Нет | Сопоставление сущностей, учёт совместных упоминаний |
| **Обобщение знаний** | Без памяти о прошлых запросах | Ментальные модели, которые объединяют и обновляют знания |
| **Черты поведения** | Нет | Три черты (скептицизм, буквальность, эмпатия) влияют на трактовку |

## Сравнение устройства

### RAG

| Шаг | Действие |
|------|-----------|
| 1 | Создать вектор запроса |
| 2 | Найти близкие векторы |
| 3 | Вернуть k лучших фрагментов |
| 4 | Создать ответ |

Один способ поиска. Состояние между запросами не хранится.

### Hindsight

| Шаг | Действие |
|------|-----------|
| 1 | Разобрать запрос: выделить указания на время и сущности |
| 2 | Выполнить четыре вида поиска параллельно: по смыслу, BM25, графу и времени |
| 3 | Объединить результаты через RRF |
| 4 | Повторно отсортировать их через кросс-энкодер |
| 5 | Учесть черты поведения |
| 6 | Создать ответ |

Несколько способов поиска. Состояние сохраняется между сеансами.

## Примеры

### Вывод через несколько связей

**Сохранённые факты:**
- «Алиса руководит технической частью проекта „Атлас“»
- «Проект „Атлас“ использует Kubernetes»
- «Во вторник произошёл сбой кластера Kubernetes»

**Запрос:** «Затронули ли Алису недавние сбои?»

| Система | Результат |
|--------|--------|
| RAG | Находит лишь факты об Алисе (по смыслу они не похожи на слово «сбои») |
| Hindsight | Проходит по связям: Алиса → проект „Атлас“ → Kubernetes → сбой |

### Запросы о времени

**Факты с датами:**
- Март: «Алиса начала переход на микросервисы»
- Апрель: «Алиса завершила службу входа»
- Октябрь: «Алиса занялась быстродействием»

**Запрос:** «Чем Алиса занималась прошлой весной?»

| Система | Результат |
|--------|--------|
| RAG | Возвращает все факты об Алисе вне зависимости от даты |
| Hindsight | Превращает «прошлой весной» в март–май и оставляет факты за этот срок |

### Понимание сущностей

**Факты о пользователе из разных сеансов:**
- «Подписка Pro»
- «Мобильное приложение падает в настройках»
- «Перешёл на годовую оплату»
- «Приложение для ПК работает без сбоев»

**Запрос:** «Что вам известно о моей учётной записи?»

| Система | Результат |
|--------|--------|
| RAG | Перечисляет отдельные факты |
| Hindsight | Через граф сущностей связывает статус подписки, оплату и известные ошибки |

### Развитие знаний

**Неделя 1:** Пользователю трудно писать асинхронный код на Python, но потоки ему подходят.
**Неделя 3:** Пользователь спрашивает об asyncio и пишет асинхронные запросы к базе.

| Система | Поведение |
|--------|----------|
| RAG | Не помнит, как менялись навыки пользователя |
| Hindsight | Создаёт модель «пользователь предпочитает синхронный код», затем уточняет её: «пользователь осваивает асинхронный код» |

## Когда что применять

| Задача | Выбор |
|----------|-------------|
| Вопросы по неизменной коллекции документов | RAG |
| Поиск без учёта времени | RAG |
| ИИ-помощник с долгой памятью | Hindsight |
| Приложение, где нужно следить за сущностями | Hindsight |
| Система, которой нужны постоянные черты поведения | Hindsight |
| Запросы о времени («в прошлом месяце», «в 2023 году») | Hindsight |
