
# Вебхуки

Hindsight может сразу сообщать приложению о событиях памяти. Для этого он отправляет HTTP-запросы POST на заданный вами адрес.

## Доставка и повторы

Вебхуки создают для каждого банка памяти. Они срабатывают сами при нужном событии. Система следит за каждой попыткой доставки и повторяет неудачные попытки, увеличивая паузу по экспоненте:

| Попытка | Пауза после ошибки |
|---------|---------------------|
| 1 | 5 секунд |
| 2 | 5 минут |
| 3 | 30 минут |
| 4 | 2 часа |
| 5 | 5 часов |
| 6 | Больше не повторять |

Доставка не удалась, если ваш адрес вернул код вне группы 2xx или не ответил за заданное время (по умолчанию 30 секунд). После шести неудачных попыток доставка помечается как окончательно проваленная и больше не повторяется.

> **ℹ️ Доставка не реже одного раза**
> 
Задача доставки попадает в очередь в той же транзакции базы, что и основная операция (например, запись retain или обобщение). Если сервер упадёт после записи в базу, но до отправки события, задача сохранится и будет выполнена позже. Поэтому **ваш адрес может получить одно событие несколько раз**. При нужде убирайте повторы по полю `operation_id`.
## Виды событий

### `consolidation.completed`

Возникает после того, как Hindsight закончил обобщать новые воспоминания банка в наблюдения.

**Данные события:**

```json
{
  "event": "consolidation.completed",
  "bank_id": "my-bank",
  "operation_id": "a1b2c3d4e5f6",
  "status": "completed",
  "timestamp": "2026-03-04T12:00:00Z",
  "data": {
    "observations_created": 3,
    "observations_updated": 1,
    "observations_deleted": null,
    "error_message": null
  }
}
```

**Поля `data`:**

| Поле | Тип | Описание |
|-------|------|-------------|
| `observations_created` | `integer \| null` | Число новых наблюдений |
| `observations_updated` | `integer \| null` | Число обновлённых наблюдений |
| `observations_deleted` | `integer \| null` | Число удалённых наблюдений |
| `error_message` | `string \| null` | Задаётся, если `status` равен `"failed"` |

**Значения `status`:** `"completed"` или `"failed"`

---

### `retain.completed`

Возникает для каждого документа после завершения retain — как синхронного, так и асинхронного. Если в пакете N документов, возникнет N отдельных событий.

**Данные события:**

```json
{
  "event": "retain.completed",
  "bank_id": "my-bank",
  "operation_id": "a1b2c3d4e5f6",
  "status": "completed",
  "timestamp": "2026-03-04T12:00:01Z",
  "data": {
    "document_id": "doc-abc123",
    "tags": ["meeting", "q1-2026"]
  }
}
```

**Поля `data`:**

| Поле | Тип | Описание |
|-------|------|-------------|
| `document_id` | `string \| null` | ID документа, если он был указан в запросе retain |
| `tags` | `string[] \| null` | Теги уровня документа, заданные при retain |

**Примечания:**
- При асинхронном retain (`async: true`) поле `operation_id` совпадает со значением, которое вернул API retain.
- При синхронном retain поле `operation_id` создаётся для слежения за вызовом.
- Для каждого элемента содержимого из запроса retain возникает одно событие.

---

### `memory_defense.triggered`

Возникает, когда правило [Memory Defense](../memory-defense/index.md) банка обработало сохранённый элемент: по одному событию на каждый **скрытый** или **заблокированный** элемент. Для элементов, прошедших проверку, события нет. В банке должно быть включено правило Memory Defense, а вебхук должен быть подписан на этот вид события.

**Данные события:**

```json
{
  "event": "memory_defense.triggered",
  "bank_id": "my-bank",
  "operation_id": "a1b2c3d4e5f6",
  "status": "redact",
  "timestamp": "2026-03-04T12:00:02Z",
  "data": {
    "action": "redact",
    "detector": "sensitive_data",
    "document_id": "doc-abc123",
    "matched_types": ["github_token", "aws_access_key"],
    "message": "Sensitive data pattern matched: github_token, aws_access_key"
  }
}
```

**Поля `data`:**

| Поле | Тип | Описание |
|-------|------|-------------|
| `action` | `string` | Действие с элементом: `"redact"` или `"block"` |
| `detector` | `string \| null` | Сработавший детектор (`"sensitive_data"`) |
| `document_id` | `string \| null` | ID документа, если он был указан в запросе retain |
| `matched_types` | `string[] \| null` | Метки сработавших шаблонов скрытия, например `github_token`, `ssn_us` |
| `message` | `string \| null` | Понятное человеку описание совпадения |

**Значения `status`:** совпадают с `data.action` — `"redact"` или `"block"`.

**Примечания:**
- Событие `redact` значит, что секрет удалён из текста, а очищенное воспоминание сохранено. Событие `block` значит, что элемент отброшен. Если заблокированы все элементы запроса retain, вызов вернёт код `422`.
