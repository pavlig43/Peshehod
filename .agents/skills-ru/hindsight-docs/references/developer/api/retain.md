# Сохранение данных: Retain

Передавайте в Hindsight документы, беседы и исходные материалы, чтобы автоматически извлекать из них воспоминания.

При вызове `retain` Hindsight не просто сохраняет исходный текст: он анализирует его, выделяет важные факты и сущности и создаёт связанные записи в графе знаний. Так неструктурированная информация становится структурированными данными, по которым можно выполнять поиск.

## Сохранение документа

Один вызов retain принимает один или несколько **элементов**. Каждый элемент — исходное содержимое: беседа, документ или заметка. Hindsight анализирует его и разбивает на одно или несколько воспоминаний. Сам текст целиком не сохраняется: в банке хранятся структурированные факты, извлечённые LLM.

### Python

```python
client.retain(
    bank_id="my-bank",
    content="Alice works at Google as a software engineer"
)
```

### Node.js

```javascript
await client.retain('my-bank', 'Alice works at Google as a software engineer');
```

### CLI

```bash
hindsight memory retain my-bank "Alice works at Google as a software engineer"
```

### Сохранение беседы

Сохраняйте всю беседу одним элементом. LLM может разобрать текстовый формат, JSON, Markdown и другие структуры, если в них понятно указано, кто и когда что сказал. В примере используется формат `Имя (время): текст`.

### Python

```python
# Сохраняем всю беседу одним документом.
# Каждое сообщение записано как "Имя (время): текст", чтобы LLM могла
# определить автора факта и разрешить относительные даты в контексте переписки.
conversation = "\n".join([
    "Alice (2024-03-15T09:00:00Z): Hi Bob! Did you end up going to the doctor last week?",
    "Bob (2024-03-15T09:01:00Z): Yes, finally. Turns out I have a mild peanut allergy.",
    "Alice (2024-03-15T09:02:00Z): Oh no! Are you okay?",
    "Bob (2024-03-15T09:03:00Z): Yeah, nothing serious. Just need to carry an antihistamine.",
    "Alice (2024-03-15T09:04:00Z): Good to know. We'll avoid peanuts at the team lunch.",
])

client.retain(
    bank_id="my-bank",
    content=conversation,
    context="team chat",
    timestamp="2024-03-15T09:04:00Z",
    document_id="chat-2024-03-15-alice-bob",
)
```

### Node.js

```javascript
// Сохраняем всю беседу одним документом.
// Каждое сообщение записано как "Имя (время): текст", чтобы LLM могла
// определить автора факта и разрешить относительные даты в контексте переписки.
const conversation = [
    'Alice (2024-03-15T09:00:00Z): Hi Bob! Did you end up going to the doctor last week?',
    'Bob (2024-03-15T09:01:00Z): Yes, finally. Turns out I have a mild peanut allergy.',
    'Alice (2024-03-15T09:02:00Z): Oh no! Are you okay?',
    'Bob (2024-03-15T09:03:00Z): Yeah, nothing serious. Just need to carry an antihistamine.',
    'Alice (2024-03-15T09:04:00Z): Good to know. We\'ll avoid peanuts at the team lunch.',
].join('\n');

await client.retain('my-bank', conversation, {
    context: 'team chat',
    timestamp: '2024-03-15T09:04:00Z',
    documentId: 'chat-2024-03-15-alice-bob',
});
```

Если беседа пополняется новыми сообщениями, повторно передайте её целиком с тем же `document_id`. Hindsight удалит предыдущую версию и обработает актуальное содержимое заново.

## Параметры

### content

Исходный текст для сохранения. Единственное обязательное поле. Hindsight делит содержимое на фрагменты, отправляет каждый фрагмент в LLM для извлечения фактов и сохраняет полученные структурированные данные, а не исходный текст. Из одного значения `content` может получиться много воспоминаний — в зависимости от объёма информации.

### timestamp

Время, когда на самом деле произошло описанное событие. Допустимы три варианта:

| Значение | Поведение |
|----------|-----------|
| Не задано или `null` | Используется время добавления данных. |
| Строка ISO 8601, например `"2024-01-15T10:30:00Z"` | Используется переданные дата и время. |
| `"unset"` | Содержимое сохраняется **без временной отметки**. Подходит для справочников, книг, вымышленных событий и других материалов без реальной даты. |

Метка времени добавляется в запрос на извлечение фактов, чтобы модель могла разрешать относительные даты в тексте. Например, если в тексте сказано «в прошлый понедельник», модель использует указанную дату как точку отсчёта. При значении `"unset"` запрос содержит `Event Date: Unknown`; тогда модель может правильно задать каждому извлечённому факту дату `N/A`. Реальная временная отметка также позволяет корректно отвечать на временные запросы Recall, например «Что произошло прошлой весной?».

### context

Краткая метка источника или ситуации: например, `"team meeting"`, `"slack"` или `"support ticket"`. Она напрямую добавляется в запрос к LLM и влияет на извлечение фактов. Одно и то же предложение может означать разное в разных контекстах: «проект закрыт» в контексте `"performance review"` даст не те же воспоминания, что в контексте `"product roadmap"`.

Последовательное заполнение контекста — один из самых действенных способов повысить качество памяти.

### metadata

Произвольные пары строковых ключей и значений, описывающие элемент. Например: `{"source": "slack", "channel": "engineering", "thread_id": "T123"}`. Метаданные передаются в запросе на извлечение фактов и помогают LLM учитывать название и источник документа. Они также сохраняются у каждой единицы памяти и возвращаются при Recall. Это позволяет фильтровать данные и дополнять их без отдельных запросов, например связать воспоминание с URL, идентификатором переписки или внутренним идентификатором приложения.

### document_id

Заданный вызывающей стороной идентификатор, объединяющий один или несколько элементов в логический документ. Это поле делает `retain` **идемпотентным**.

Если документ с таким `document_id` уже есть, Hindsight заменяет его: удаляет документ и связанные воспоминания, затем обрабатывает и добавляет новое содержимое. Поэтому обновлённый чат можно сохранять повторно без накопления дубликатов.

Если `document_id` не указан, для каждого запроса создаётся случайный UUID. Повторная загрузка того же содержимого создаст дубликаты воспоминаний.

### update_mode

Определяет, как обрабатывать существующий документ при сохранении с уже используемым `document_id`.

| Значение | Поведение |
|----------|-----------|
| `"replace"` *(по умолчанию)* | Удаляет старый документ и связанные воспоминания, затем обрабатывает новое содержимое с нуля. Это стандартная замена, описанная выше. |
| `"append"` | Добавляет новое содержимое в конец текста документа и повторно обрабатывает объединённый документ. При использовании delta retain пропускает неизменившиеся фрагменты, поэтому LLM извлекает факты только из новой части. |

Для append обязательно указывать `document_id`: без него не к чему добавлять данные.

**Когда использовать append:** для данных, которые пополняются постепенно, например журнала, дневника или переписки с новыми сообщениями. Вместо повторной отправки всей истории передавайте только новые сведения с `update_mode: "append"`.

```json
{
  "items": [
    {
      "content": "New entry to add to the existing document.",
      "document_id": "my-growing-doc",
      "update_mode": "append"
    }
  ]
}
```

### entities

Список сущностей, распознавание которых нужно гарантировать. Они объединяются с сущностями, автоматически извлечёнными LLM. В каждой записи обязательно поле `text` с названием сущности и, при необходимости, поле `type` (например, `"PERSON"`, `"ORG"`, `"CONCEPT"`; если не задано, используется `"CONCEPT"`).

Используйте этот параметр, если важные сущности могут быть пропущены моделью или неодинаково названы в разных частях содержимого. Явно заданные сущности всегда будут связаны в графе знаний.

### tags и document_tags

Метки управляют **областью видимости** воспоминаний при Recall. Воспоминание возвращается, только если его метки подходят к фильтру запроса Recall. Это полезно, если один банк памяти используется несколькими пользователями или сеансами и каждый должен видеть только свои воспоминания.

Используйте единообразные шаблоны: `user:<id>` для пользователя, `session:<id>` для изоляции сеанса, `room:<id>` для чата, `topic:<name>` для фильтрации по теме. В банке есть конечная точка со списком меток и числом воспоминаний для каждой: она полезна для автодополнения и поиска по маске.

Фильтрация при извлечении описана в разделе [API Recall](./recall#tags).

### observation_scopes

Определяет, каким [наблюдениям](../observations) это воспоминание будет помогать при консолидации. Для каждой области выполняется отдельный проход; создаются или обновляются наблюдения с метками только этой области.

> **ℹ️ Изоляция областей**
>
> При консолидации Hindsight ищет наблюдения для обновления со строгим совпадением `all_strict`: учитываются только наблюдения с точно таким же набором меток, что и текущая область. Области изолированы — воспоминание, сведённое в наблюдение с меткой `["student:alice"]`, не попадёт в наблюдение с метками `["student:alice", "teacher:bob"]`.

Далее рассматривается стенограмма урока с `tags: ["student:alice", "teacher:bob", "session-id:s1"]`.

#### combined *(по умолчанию)*

Один проход консолидации сразу по всем меткам. Созданное наблюдение получает полный список меток.

- Создаётся наблюдение с метками `["student:alice", "teacher:bob", "session-id:s1"]`.
- ✗ «С чем Алисе трудно справляться во всех занятиях?» — нет совпадения: отдельного наблюдения только для `student:alice` нет.
- ✗ «Как Боб ведёт занятия?» — нет совпадения только по `teacher:bob`.
- ✓ «Что произошло на занятии s1 с Алисой и Бобом?» — точное совпадение.

**Используйте**, если воспоминание имеет смысл только целиком и не требуется отдельно искать по каждой метке.

#### shared

Один проход консолидации в общей глобальной **области без меток**. Собственные метки воспоминания не учитываются для наблюдений, но сохраняются в исходных фактах и продолжают использоваться фильтрами Recall. Воспоминания с **разными** метками объединяются в одни и те же наблюдения.

- Создаётся одно наблюдение без меток (`[]`).
- ✓ Глобальные наблюдения без меток подходят для любого запроса Recall, независимо от фильтра меток.
- Сокращает дублирование для временных меток отдельного вызова. Если каждому сеансу присваивается уникальная метка `session-id:…`, режимы `combined` и `per_tag` создадут отдельное наблюдение для каждого сеанса; `shared` объединит их.

**Используйте**, если метки обозначают происхождение данных (например, ID сеанса) и нужны для фильтрации и отладки при Recall, но не должны разделять консолидацию. Оставьте их в `tags` и задайте `observation_scopes: "shared"`.

> **🚨 `shared`, `[[]]` и `[]` — разные значения**
>
> `shared` эквивалентен явной области `[[]]` — списку с одной пустой областью. Не путайте его с `[]` (пустым списком), который задаёт **ноль областей** и молча переключает режим на `combined`.

#### per_tag

Отдельный проход консолидации для каждой метки. Для каждой метки создаётся изолированное наблюдение, которое пополняется с каждым новым воспоминанием с этой меткой.

- Создаются области `["student:alice"]`, `["teacher:bob"]`, `["session-id:s1"]`.
- ✓ «С чем Алисе трудно справляться во всех занятиях?»
- ✓ «Как Боб ведёт занятия?»
- ✓ «Что произошло на занятии s1?»
- ✗ «Как Алиса занимается именно с Бобом?» — нет наблюдения для сочетания `["student:alice", "teacher:bob"]`.
- ✗ «Как Боб преподаёт на онлайн-занятиях?» — нет наблюдения для `["teacher:bob", "session-id:s1"]`.

**Используйте**, когда у нескольких участников или аспектов содержимого независимые метки. Обычно это лучший выбор для бесед, уроков и обращений в поддержку с несколькими участниками.

#### all_combinations

Отдельный проход для каждой подгруппы меток: одиночных, парных, тройных и далее. Для трёх меток выполняется семь проходов.

- Создаются все области `per_tag`, а также пары `["student:alice", "teacher:bob"]`, `["student:alice", "session-id:s1"]`, `["teacher:bob", "session-id:s1"]` и вся тройка.
- ✓ Подходят все вопросы для `per_tag`.
- ✓ «Как Алиса занимается именно с Бобом?» — совпадает с `["student:alice", "teacher:bob"]`.

**Используйте**, если нужны наблюдения на всех уровнях: по отдельной метке, паре меток и группе.

#### custom

Передайте конкретный список наборов меток. Каждый вложенный список задаёт одну область.

```json
[["student:alice"], ["teacher:bob"], ["teacher:bob", "session-id:s1"]]
```

- Создаются только три указанные области.
- ✓ «С чем Алисе трудно справляться?»
- ✓ «Как Боб преподаёт?»
- ✓ «Как Боб преподаёт именно на занятии s1?»
- ✗ «Что произошло на занятии s1 независимо от учителя?» — область `["session-id:s1"]` не задана.

**Используйте**, если точные значимые сочетания известны заранее и лишние проходы нежелательны.

### Ответ

Синхронный ответ retain содержит:

- `success` — успешно ли завершилась операция;
- `bank_id` — банк памяти, куда добавлено содержимое;
- `items_count` — число обработанных элементов;
- `async` — выполнялась ли обработка асинхронно;
- `usage` — число токенов в запросах LLM (`input_tokens`, `output_tokens`, `total_tokens`); есть только у синхронных операций.

## Пакетная загрузка

Несколько элементов можно отправить одним запросом. Это рекомендуется: уменьшается сетевой обмен, и Hindsight может оптимизировать извлечение по связанным материалам.

```python
client.retain_batch(
    bank_id="my-bank",
    items=[
        {"content": "Alice works at Google", "context": "career", "document_id": "conversation_001_msg_1"},
        {"content": "Bob is a data scientist at Meta", "context": "career", "document_id": "conversation_001_msg_2"},
        {"content": "Alice and Bob are friends", "context": "relationship", "document_id": "conversation_001_msg_3"}
    ]
)
```

### Node.js

```javascript
await client.retainBatch('my-bank', [
    { content: 'Alice works at Google', context: 'career', document_id: 'conversation_001_msg_1' },
    { content: 'Bob is a data scientist at Meta', context: 'career', document_id: 'conversation_001_msg_2' },
    { content: 'Alice and Bob are friends', context: 'relationship', document_id: 'conversation_001_msg_3' }
]);
```

В CLI элементы обрабатываются по одному отдельными вызовами `retain`.

## Файлы

Загружайте файлы напрямую: Hindsight преобразует их в текст и автоматически извлечёт воспоминания. Обработка файлов всегда асинхронна; для отслеживания возвращаются идентификаторы операций.

**Поддерживаемые форматы:** PDF, DOCX, DOC, PPTX, PPT, XLSX, XLS, изображения (JPG, PNG, GIF и другие; распознавание текста OCR зависит от настроенного обработчика), аудио (MP3, WAV, FLAC и другие; преобразование речи в текст), HTML, простой текст (TXT, MD, CSV, JSON, YAML и другие).

```python
# Загружает файлы и сохраняет их содержимое как воспоминания.
# Поддерживаются PDF, DOCX, PPTX, XLSX, изображения (OCR), аудио и текстовые форматы.
# Передайте пути к файлам — клиент сам прочитает и загрузит их.
result = client.retain_files(
    bank_id="my-bank",
    files=[EXAMPLES_DIR / "sample.pdf"],
    context="quarterly report",
)
print(result.operation_ids)  # Отслеживание через конечную точку операций
```

```bash
# Загрузить один файл
hindsight memory retain-files my-bank "$SAMPLE_FILE"

# Загрузить папку
hindsight memory retain-files my-bank "$SCRIPT_DIR/"

# Поставить файлы в очередь для фоновой обработки
hindsight memory retain-files my-bank "$SCRIPT_DIR/" --async
```

Конечная точка загрузки файлов всегда возвращается асинхронно. Ответ содержит `operation_ids` — по одному на каждый файл. Отслеживайте ход обработки через `GET /v1/default/banks/{bank_id}/operations`.

Один запрос может содержать до 10 файлов общим объёмом не более 100 МБ. Каждый файл становится отдельным документом с необязательными метаданными:

```python
# До 10 файлов за пакет, каждому можно задать собственные метаданные.
result = client.retain_files(
    bank_id="my-bank",
    files=[
        EXAMPLES_DIR / "sample.pdf",
        EXAMPLES_DIR / "sample.pdf",  # Замените путём ко второму файлу
    ],
    files_metadata=[
        {"context": "quarterly report", "document_id": "q1-report", "tags": ["project:alpha"]},
        {"context": "meeting notes", "document_id": "q1-notes", "tags": ["project:alpha"]},
    ],
)
print(result.operation_ids)  # Идентификатор операции для каждого файла
```

Загруженные файлы хранятся на сервере: по умолчанию в PostgreSQL, либо в S3, GCS или Azure для production. Тип хранилища задаётся `HINDSIGHT_API_FILE_STORAGE_TYPE`. Подробнее — [настройка обработки файлов](../configuration#file-processing).

## Асинхронная загрузка

Для больших пакетов используйте асинхронную загрузку, чтобы не блокировать приложение.

```python
# Запускает фоновую загрузку и сразу возвращает ответ
result = client.retain_batch(
    bank_id="my-bank",
    items=[
        {"content": "Large batch item 1", "document_id": "large-doc-1"},
        {"content": "Large batch item 2", "document_id": "large-doc-2"},
    ],
    retain_async=True
)

# Проверка асинхронной обработки
print(result.var_async)  # True
```

При `async: true` вызов сразу возвращает `operation_id`; обработка выполняется в фоне через службу worker. Метрики `usage` для таких операций не возвращаются.

### Сократите стоимость на 50% с пакетными API поставщиков

При асинхронном retain включите пакетный API поставщика, чтобы вдвое сократить стоимость извлечения фактов. OpenAI, Groq и Gemini предоставляют такую скидку в обмен на время обработки до 24 часов. Обычно эта задержка незаметна, поскольку retain и так выполняется в фоне.

```bash
export HINDSIGHT_API_RETAIN_BATCH_ENABLED=true
```

Hindsight отправляет запросы извлечения фактов поставщику одним пакетным заданием, проверяет готовность и автоматически обрабатывает результаты. Изменять вызовы API не требуется.

> **📝 Примечание**
>
> Экономия через пакетный API доступна, только если в запросе retain задано `async=true` и используется совместимый поставщик: OpenAI, Groq или Gemini.
