# Защита памяти (Memory Defense)

Hindsight удаляет секреты и персональные данные из текста для retain с помощью 45 регулярных шаблонов. Каждое совпадение заменяется меткой `[REDACTED:type]` до записи в единицы памяти или тело документа. Эту функцию настраивают отдельно для каждого банка; по умолчанию она выключена.

## Как это работает

Защиту памяти включают отдельно в каждом банке. Расширение есть всегда, но ничего не делает, пока банку не зададут включающее его правило. После этого каждое записываемое в банк воспоминание проходит проверку перед сохранением. Если проверка найдёт учётные данные, ключ API, строку подключения к базе или известный формат персональных данных, найденный фрагмент заменится меткой вроде `[REDACTED:github_token]`.

В хранилище попадает очищенный текст. Единицы памяти и тела документов хранят его без секрета, поэтому будущие ответы recall, выгрузки и операции reflect не увидят исходный секрет.

Правило действует лишь на будущие вызовы retain в этом банке. При добавлении или смене правила уже сохранённые воспоминания не проверяются задним числом.

## Настройка защиты памяти

Защиту задают для банка в поле `memory_defense`. Правило можно указать при создании банка либо позже через `PATCH /v1/{tenant}/banks/{bank_id}/config`.

В открытой версии есть правило `sensitive_data` с двумя действиями:

- **`redact`** — заменить каждый найденный секрет меткой `[REDACTED:type]` и сохранить очищенное воспоминание.
- **`block`** — отбросить любой элемент с совпадением. Если заблокированы все элементы запроса retain, вызов вернёт `422`.

Простое правило:

```json
{
  "memory_defense": {
    "enabled": true,
    "rules": [
      { "on": "sensitive_data", "action": "redact" }
    ]
  }
}
```

После включения правила каждый вызов retain для банка проверяется 45 шаблонами, список которых приведён ниже.

:::note Существующие воспоминания не проверяются задним числом
Включение защиты влияет лишь на будущие вызовы retain. Воспоминания, уже лежащие в банке, не проверяются и не меняются при добавлении или смене правила. Если в банке есть неочищенные данные, вам придётся загрузить затронутые воспоминания заново или удалить их вручную.
:::

### По умолчанию выключена

Защита памяти выключена в каждом банке, пока вы не зададите правило. Если нет поля `memory_defense`, стоит `enabled: false` или нет правила `sensitive_data`, итог один: расширение возвращает ALLOW, а текст проходит без правок. Чтобы прекратить скрывать данные в банке, задайте `enabled: false` или удалите правило.

## Уведомления

Когда элемент скрыт или заблокирован, Hindsight отправляет [вебхук `memory_defense.triggered`](../api/webhooks.mdx#memory_defensetriggered), если вебхук банка подписан на это событие. В данных указаны действие, ID документа и сработавшие шаблоны. Это помогает направлять сообщения о безопасности в SIEM или Slack. Для чистых элементов события нет.

Решения о скрытии и блокировке также попадают в [журнал аудита](../configuration.md#audit-logging) как записи `memory_defense` (если журнал включён). Действие и метки шаблонов сохраняются в метаданных записи.
