# Работа с разными языками

Hindsight сам определяет язык исходного текста и отвечает на нём. Факты, сущности и ответы reflect остаются на исходном языке и не переводятся на английский.

## Как это работает

```mermaid
graph LR
    A[Chinese Input] --> B[Language Detection]
    B --> C[Extract Facts in Chinese]
    C --> D[Chinese Entities]
    D --> E[Chinese Response]
```

При сохранении текста или вызове reflect Hindsight:

1. **Определяет язык** по содержимому.
2. **Извлекает факты на исходном языке**, сохраняя оттенки смысла.
3. **Хранит имена сущностей в исходной письменности**: 张伟 остаётся 张伟, а не превращается в «Zhang Wei».
4. **Отвечает на том же языке**: на запрос по-китайски даёт ответ по-китайски.

---

## Retain для текста не на английском

При сохранении текста на любом языке Hindsight извлекает и хранит факты на том же языке.

### Пример: китайский текст

```python
from hindsight import Hindsight

hindsight = Hindsight()

# Retain Chinese content
hindsight.retain(
    bank_id="user-123",
    content="""
    张伟是一位资深软件工程师，在腾讯工作了五年。
    他专门研究分布式系统，并领导了公司微服务架构的开发。
    """,
    context="团队概述"
)

# Query in Chinese - get Chinese results
results = hindsight.recall(
    bank_id="user-123",
    query="告诉我关于张伟的信息"
)

# Facts are returned in Chinese:
# - 张伟是一位资深软件工程师，在腾讯工作了五年
# - 张伟专门研究分布式系统，并领导了公司微服务架构的开发
```

### Пример: японский текст

```python
hindsight.retain(
    bank_id="user-123",
    content="""
    田中さんはソフトウェアエンジニアで、東京のスタートアップで働いています。
    彼女はPythonとTypeScriptが得意で、毎日コードレビューをしています。
    """,
    context="チームプロフィール"
)

# Query in Japanese
results = hindsight.recall(
    bank_id="user-123",
    query="田中さんについて教えてください"
)
```

## Reflect для запросов на других языках

Операция `reflect` также учитывает язык запроса и создаёт ответ на нём.

### Пример: рассуждение на китайском

```python
# Store facts about team members (in Chinese)
hindsight.retain(
    bank_id="team-eval",
    content="张伟是一位优秀的软件工程师，完成了五个重大项目。他总是按时交付，代码整洁有良好的文档。",
    context="绩效评估"
)

hindsight.retain(
    bank_id="team-eval",
    content="李明最近加入团队。他错过了第一个截止日期，代码有很多bug。",
    context="绩效评估"
)

# Reflect in Chinese
result = hindsight.reflect(
    bank_id="team-eval",
    query="谁是更可靠的工程师？"
)

# Response is in Chinese:
# "我认为张伟更可靠。张伟完成了五个重大项目，按时交付，代码质量高..."
```

## Текст на нескольких языках

Hindsight умеет работать и со смешанным текстом, сохраняя оба языка, где это уместно.

### Пример: китайский текст с английскими именами компаний

```python
hindsight.retain(
    bank_id="user-123",
    content="""
    王芳在Google北京办公室工作，她是一名高级产品经理。
    之前她在Microsoft和Amazon工作过。
    她负责管理YouTube在中国市场的推广策略。
    """,
    context="员工资料"
)

# Facts preserve both languages:
# - 王芳在Google北京办公室工作，担任高级产品经理
# - 王芳曾在Microsoft和Amazon工作过
# - 王芳负责管理YouTube在中国市场的推广策略
```

## Поддерживаемые языки

**Работа Hindsight с разными языками целиком зависит от языковых навыков вашей LLM.** Hindsight просит LLM определить язык текста и ответить на нём. Если LLM знает язык, Hindsight сможет с ним работать.

Большинство новых LLM (GPT-4, Claude, Gemini, Llama 3 и др.) знают десятки языков, среди них:

- **Восточная Азия**: китайский (упрощённое и традиционное письмо), японский, корейский.
- **Европа**: испанский, французский, немецкий, итальянский, португальский, нидерландский, польский, русский.
- **Ближний Восток**: арабский, иврит, турецкий.
- **Южная Азия**: хинди, бенгальский, тамильский.
- **Юго-Восточная Азия**: тайский, вьетнамский, индонезийский.

**Чтобы проверить нужный язык**, дайте своей LLM текст на нём. Если она понимает и создаёт такой текст, Hindsight сможет сохранить его язык.

## Настройка для разных языков

Для хорошей работы настройте все четыре части цепочки.

### 1. LLM (обязательно)
Ваша LLM должна знать нужные языки. Большинство новых моделей знают, но проверьте именно свою.

### 2. Модель векторов (советуем)
Модель по умолчанию (`BAAI/bge-small-en-v1.5`) работает **только с английским**. Для другого языка поставьте многоязычную модель:

```bash
# In your .env file
HINDSIGHT_API_EMBEDDINGS_LOCAL_MODEL=BAAI/bge-m3
```

**Советуемые многоязычные модели векторов:**
| Модель | Языки | Примечания |
|-------|-----------|-------|
| `BAAI/bge-m3` | 100+ | Лучшее общее качество на разных языках |
| `intfloat/multilingual-e5-large` | 100+ | Хорошая замена |
| `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | 50+ | Более лёгкая модель |

### 3. Модель повторной сортировки (советуем)
Модель по умолчанию (`cross-encoder/ms-marco-MiniLM-L-6-v2`) работает **только с английским**. Для другого языка поставьте многоязычную модель:

```bash
# In your .env file
HINDSIGHT_API_RERANKER_LOCAL_MODEL=BAAI/bge-reranker-v2-m3
```

**Советуемые многоязычные модели сортировки:**
| Модель | Языки | Примечания |
|-------|-----------|-------|
| `BAAI/bge-reranker-v2-m3` | 100+ | Лучшее качество повторной сортировки |
| `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` | 14 | Более лёгкая замена |

### 4. Система BM25 / полнотекстового поиска

Семантический поиск по векторам находит совпадения по смыслу между разными языками. Параллельно Hindsight запускает поиск BM25 по словам. **BM25 работает внутри одного языка**: он сопоставляет символы и токены по правилам разбиения слов. Встроенный вариант `native` берёт английский словарь PostgreSQL. Для текста не на английском результат хуже, а для китайского, японского и корейского, где между словами нет пробелов, полезного разбиения вовсе нет.

На работу влияют две настройки:

- `HINDSIGHT_API_TEXT_SEARCH_EXTENSION` — выбирает движок (`native`, `vchord`, `pg_textsearch`, `pgroonga` или `pg_search`).
- `HINDSIGHT_API_TEXT_SEARCH_EXTENSION_NATIVE_LANGUAGE` — выбирает словарь PostgreSQL для `native` (по умолчанию `english`).

Выберите движок по языкам банка:

| Движок | Разные языки / CJK | Примечания |
|---------|--------------------|-------|
| `native` | Только языки Европы (английский, французский, немецкий, испанский, итальянский, португальский, русский, нидерландский, шведский, норвежский, датский, финский, венгерский, турецкий, арабский, а также `simple`). Для CJK нужен сторонний словарь вроде `zhparser`. | Обычный PostgreSQL без новых расширений. Язык задаётся через `HINDSIGHT_API_TEXT_SEARCH_EXTENSION_NATIVE_LANGUAGE`. |
| `vchord` | Разные языки через разбиение `llmlingua2`. | Удобно, если для поиска по векторам уже взят vchord. |
| `pg_textsearch` | Только английский (зашит в коде). | Сортировка BM25 по общему стандарту и Block-Max WAND. |
| `pgroonga` | **Да, сразу после установки.** Один индекс работает с английским, CJK и смешанным текстом через разбиение `TokenBigram` и нормализацию Unicode `NormalizerNFKC150`. | Советуем для банков не на английском или со смешанным текстом. Нужно расширение `pgroonga`. См. `docker/docker-compose/pgroonga/`. |
| `pg_search` | Разные языки через настраиваемое разбиение (например, `chinese_compatible`, `jieba`, `chinese_lindera`, `japanese_lindera`, `korean_lindera`, `ngram`). | Расширение ParadeDB `pg_search` — единственный движок BM25, совместимый с Citus. Разбиение задаётся через `HINDSIGHT_API_TEXT_SEARCH_EXTENSION_PG_SEARCH_TOKENIZER`. См. `docker/docker-compose/pg_search/`. |

**Выбор для банка с одним языком** (например, только испанский):
```bash
HINDSIGHT_API_TEXT_SEARCH_EXTENSION=native
HINDSIGHT_API_TEXT_SEARCH_EXTENSION_NATIVE_LANGUAGE=spanish
```

**Выбор для банка с CJK или разными языками**:
```bash
HINDSIGHT_API_TEXT_SEARCH_EXTENSION=pgroonga
```

Настройки `native` и `pgroonga` не влияют друг на друга. Способ разбиения `pgroonga` задаётся при создании индекса и не учитывает `HINDSIGHT_API_TEXT_SEARCH_EXTENSION_NATIVE_LANGUAGE`.

#### Принудительный выбор языка LLM

Независимо от движка BM25 переменная `HINDSIGHT_API_LLM_OUTPUT_LANGUAGE` заставляет LLM создавать всё на одном языке вне зависимости от языка источника. Это действует для:

- **Retain** — текста фактов, контекста и имён сущностей из документов.
- **Обобщения** — наблюдений и ментальных моделей из этих фактов.
- **Reflect** — итогового ответа обычным языком, возвращаемого API reflect.

```bash
# Every LLM call (retain, consolidation, reflect) emits Spanish regardless of source language.
HINDSIGHT_API_LLM_OUTPUT_LANGUAGE=Spanish
```

Частые схемы:
- **Банк с одним заданным языком**: `HINDSIGHT_API_TEXT_SEARCH_EXTENSION_NATIVE_LANGUAGE=spanish` + `HINDSIGHT_API_LLM_OUTPUT_LANGUAGE=Spanish`. Хранит, индексирует и возвращает ответ по-испански даже при смешанных источниках.
- **Банк с разными языками и многоязычным индексом**: `HINDSIGHT_API_TEXT_SEARCH_EXTENSION=pgroonga`, а `HINDSIGHT_API_LLM_OUTPUT_LANGUAGE` не задан. Факты остаются на языке источника, pgroonga ищет по всем в одном индексе, reflect отвечает на языке запроса.
- **Общий язык для разных источников**: `HINDSIGHT_API_LLM_OUTPUT_LANGUAGE=English`. Все факты, наблюдения и ответы reflect будут по-английски вне зависимости от источника. Удобно, если получатель (LLM только с английским, панель или следующая часть цепочки) ждёт единый язык.

Не задавайте `HINDSIGHT_API_LLM_OUTPUT_LANGUAGE`, чтобы оставить язык источника или запроса во всей цепочке. Это поведение по умолчанию.

## Советы по работе

### 1. Для текста не на английском берите многоязычные модели
Если вы в основном работаете с другим языком, настройте многоязычные модели векторов и повторной сортировки. Модели только для английского тоже сохранят текст правильно, но смысловой поиск станет хуже.

### 2. Один язык на вызов Retain
Смешанный текст поддерживается, но один язык в каждом вызове `retain` даёт более ровный результат.

### 3. Ищите на языке сохранённого текста
Лучше искать на том же языке, что и хранимый текст. Запрос на другом языке (например, английский запрос к китайскому тексту) может сработать, но результат зависит от модели векторов.

## Технические детали

Работа с языками основана на указаниях для LLM, а не на сторонних библиотеках распознавания языка. Такой подход:

- **Не требует новых зависимостей**.
- **Работает с любой LLM**, которая знает несколько языков.
- **Сам обрабатывает сложные случаи**, например смешанный текст.
- **Лучше сохраняет смысл**, чем перевод по набору правил.

LLM получает указания:
1. Определить язык текста.
2. Извлечь все факты, сущности и описания на этом языке.
3. Никогда не переводить на английский, кроме случаев, когда исходный текст уже на английском.
