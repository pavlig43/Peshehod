# Гибкий дизайн Compose Multiplatform

## Назначение

Используйте навык при создании или проверке гибкого интерфейса Compose Multiplatform. Для всех платформ нужна одна общая модель, а код отдельной платформы добавляйте лишь там, где без него нельзя, особенно для больших экранов Android, складных устройств и нескольких окон.

## Когда применять

- Общий интерфейс Compose должен работать на телефоне, планшете, складном устройстве и в окне компьютера.
- Нужно заменить жёсткую телефонную разметку гибкой.
- Нужен экран «список и детали», вспомогательная панель или лента.
- Нужно выбрать нижнюю панель, боковую панель или меню навигации по ширине окна.
- Нужно учесть смену размера и поворота окна, разделённый экран или оконный режим компьютера.
- Нужно сохранить состояние при складывании и раскладывании устройства или смене размера.
- Нужно проверить гибкую разметку и частые ошибки.

## Обязательные правила

1. Выбирайте разметку по размеру окна приложения, а не по виду устройства.
2. Решения о гибкой разметке держите вместе в состоянии уровня приложения.
3. Поднимайте состояние вверх и сохраняйте односторонний поток данных; не загружайте разные наборы данных из-за класса ширины.
4. Не закрепляйте поворот экрана или соотношение сторон.
5. Не берите устаревшие API Display для расчёта размера.
6. Делайте длинное содержимое прокручиваемым, чтобы управление оставалось доступным.
7. При смене размера и настроек сохраняйте выбор, положение прокрутки, ввод и место воспроизведения.

## Порядок работы

### 1. Сначала сделайте общую модель

- Определите общий `AppAdaptiveState` по текущей ширине и высоте окна, при нужде добавьте положение складного устройства.
- Один раз выведите из него правила и признаки, например `showNavRail`, `useTwoPane`, `showTopBar`.
- Передавайте состояние вниз явными параметрами.

Прочитайте `references/adaptive-architecture.md`.

### 2. Выберите навигацию приложения по ширине

- Узкое окно: нижняя навигация или один экран за раз.
- Средняя ширина: обычно удобнее боковая панель навигации.
- Широкое и шире: боковая панель с постоянно видимыми областями либо выдвижное меню при большом числе разделов.

Прочитайте `references/canonical-layouts.md`.

### 3. Выберите типовую разметку содержимого

- «Список и детали» — когда пользователь выбирает элемент и изучает его.
- Вспомогательная панель — когда второе содержимое имеет смысл лишь рядом с главным.
- Лента — когда есть много равноправных карточек с гибким числом столбцов.

Прочитайте `references/canonical-layouts.md`.

### 4. Вложенные элементы подстройте по их месту

- На уровне приложения и экрана берите классы размера окна.
- Во вложенных элементах берите местные ограничения: `BoxWithConstraints`, свой `Layout`, модификаторы.
- Не привязывайте повторно используемый вложенный элемент к общему состоянию окна.

Прочитайте `references/adaptive-architecture.md` и `references/advanced-compose-layout-primitives.md`.

### 5. Где нужно, учтите Android

- Для Android согласуйте поведение больших экранов с API 36+.
- Учтите несколько окон, заголовок окна компьютера, складные устройства и внешние экраны.
- Для просмотра камеры на складном устройстве предпочитайте современные средства.

Прочитайте `references/android-large-screen-foldables.md`.

### 6. Проверьте матрицу размеров

- Испытайте узкую, среднюю и широкую ширину, а также малую, среднюю и большую высоту.
- Испытайте живое изменение размера, разделённый экран, окна компьютера, складывание, раскладывание и смену экрана.
- Убедитесь, что состояние не теряется, а органы управления доступны.

Прочитайте `references/testing-playbook.md`.

## Заметки по реализации

- Где доступны для целевой платформы, предпочитайте API Material 3 Adaptive: `NavigationSuiteScaffold`, `ListDetailPaneScaffold`, `SupportingPaneScaffold`, `NavigableListDetailPaneScaffold`, `NavigableSupportingPaneScaffold`.
- Доступность зависит от платформы и версии. Если API нет, повторите те же правила панелей и навигации через общий `AppAdaptiveState` и обычную разметку Compose.
- Для возврата с предпросмотром в гибких контейнерах навигации на Android 15 и ниже включите `android:enableOnBackInvokedCallback="true"`; на Android 16+ он включён по умолчанию.

## Краткая проверка

- [ ] Правила гибкой разметки выводятся один раз на верхнем уровне.
- [ ] Разметку не выбирают через `isTablet` или признаки физического устройства.
- [ ] Типовая схема соответствует задаче: список и детали, вспомогательная панель или лента.
- [ ] Вложенные элементы используют местные ограничения, а не общее состояние окна.
- [ ] Выбор и ввод сохраняются при смене размера, складывании и работе с несколькими окнами.
- [ ] Где нужно, учтены большие экраны и складные устройства Android.
