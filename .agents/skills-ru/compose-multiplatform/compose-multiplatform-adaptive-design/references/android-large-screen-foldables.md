## 1. Перемены API 36

Для приложений с целью Android 16 (API 36) на экране с наименьшей шириной `>= 600dp` система игнорирует ограничения поворота, соотношения сторон и смены размера окна.

Это касается планшетов, внутренних экранов складных устройств и оконного режима компьютера.

По версиям:

- В API 36 можно временно отказаться от нового поведения через свойство манифеста.
- В API 37+ такой отказ убран: при `sw >= 600dp` ограничения всегда игнорируются.

## 2. Манифест и поведение во время работы

Делайте `Activity` гибкими и допускающими смену размера; убирайте фиксацию поворота и пропорций у обычного интерфейса; применяйте API размеров окна и классы размеров.

Избегайте:

- `android:resizeableActivity="false"` как приёма разметки;
- жёсткого `screenOrientation` для общего интерфейса;
- `minAspectRatio` и `maxAspectRatio` у гибких экранов.

Если на API 36 нужно временно сохранить старое поведение, используйте `android.window.PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY`.

## 3. Несколько окон и оконный режим компьютера

- На новых больших экранах работа в нескольких окнах — штатный случай.
- Размер окна может часто меняться: берегите состояние и не допускайте мигания разметки.
- Учитывайте системный заголовок окна через отступы `captionBar`.
- Когда несколько окон могут быть активны сразу, осторожно выдавайте исключительные ресурсы, например камеру и микрофон.

Полезные API и флаги: `isInMultiWindowMode()`, `onMultiWindowModeChanged()`, `FLAG_ACTIVITY_LAUNCH_ADJACENT` вместе с `FLAG_ACTIVITY_NEW_TASK`, `WindowManager#getCurrentWindowMetrics()`, `WindowManager#getMaximumWindowMetrics()`.

## 4. Внешние экраны

При подключении экрана могут смениться ID экрана, плотность, частота, свойства HDR и доступные границы.

Правила:

- Для сведений, зависящих от экрана, берите контекст `Activity` или интерфейса, а не приложения.
- При смене плотности перестраивайте разметку и масштаб ресурсов.
- Не ограничивайте функции больших экранов списком моделей устройств.
- Поддерживайте клавиатуру, мышь, сенсорную панель и внешние устройства для медиа.

Запуск на нужном экране:

```kotlin
val options = ActivityOptions.makeBasic()
options.setLaunchDisplayId(targetDisplayId)
startActivity(intent, options.toBundle())
```

## 5. Складные устройства и их положение

Через Jetpack WindowManager (`WindowInfoTracker`) наблюдайте `WindowLayoutInfo` и `FoldingFeature`:

- `state`: `FLAT` или `HALF_OPENED`;
- `orientation`: `HORIZONTAL` или `VERTICAL`;
- `occlusionType`: `NONE` или `FULL`;
- `isSeparating`: делит ли складка или шарнир рабочую область.

Положение «стол»: `HALF_OPENED` с горизонтальной складкой. Положение «книга»: `HALF_OPENED` с вертикальной. Когда шарнир делит области, не ставьте управление на складке.

Для устройств с тремя частями и складкой поперёк широкого экрана не считайте исходный поворот всегда вертикальным; учитывайте смену плотности между внешним и внутренним экранами; храните состояние при складывании, раскладывании и смене положения.

## 6. Просмотр камеры

Предпочтительный порядок:

1. CameraX с `PreviewView` — стандартный выбор.
2. CameraViewfinder, если проект уже построен на Camera2.
3. Ручные преобразования Camera2 лишь при нужде.
4. Системный вызов камеры для простого снимка.

Не предполагайте, что поворот датчика равен повороту приложения, смена пропорций означает смену поворота или границы полного экрана равны доступному окну приложения.

## 7. Опасные ошибки

- Интерфейс растянут без предела ширины.
- В низком окне нет прокрутки.
- Просмотр камеры искажается после складывания, раскладывания или смены размера.
- При пересоздании `Activity` после смены настроек теряется состояние.
- При переносе между экранами с разной плотностью сохраняется старый масштаб ресурсов.
