## Основной порядок работы

- [ ] **Шаг 1:** создайте `R8_Configuration_Analysis.md` для результата либо используйте готовый файл.
- [ ] **Шаг 2:** изучите настройку R8 в `build.gradle`, `build.gradle.kts` и `gradle.properties` проекта, опираясь на [references/CONFIGURATION.md](references/CONFIGURATION.md). Сообщите разработчику и внесите разбор в отчёт.
- [ ] **Шаг 3:** если версия AGP ниже 9, предложите перейти на AGP 9.0: в нём есть [улучшения](references/android/topic/performance/app-optimization/enable-app-optimization.md).
- [ ] **Шаг 4:** изучите файлы ProGuard и оцените каждое правило сохранения строго по порядку:
  1. **Библиотеки:** сравните правила с [references/REDUNDANT-RULES.md](references/REDUNDANT-RULES.md). Если правила приложения касаются Google, AndroidX, Kotlin, Kotlinx, Room, Gson или Retrofit, сообщите, что они не нужны, и предложите их убрать.
  2. **Влияние:** оставшиеся правила оцените по иерархии из [references/KEEP-RULES-IMPACT-HIERARCHY.md](references/KEEP-RULES-IMPACT-HIERARCHY.md). Не оценивайте вновь правила, уже охваченные проверкой библиотек.
- [ ] **Шаг 5:** среди оставшихся правил найдите те, которые перекрывают другие, по той же иерархии. Предложите убрать более широкие правила.
- [ ] **Шаг 6:** для каждого оставшегося правила изучите затронутый код и соседние файлы: зачем правило было написано? Ищите отражение в этих пакетах и предложите узкое правило под конкретный случай с опорой на [references/REFLECTION-GUIDE.md](references/REFLECTION-GUIDE.md).
- [ ] **Шаг 7:** для каждого правила кратко скажите, что сделать: убрать или сузить. Если сузить — покажите, как найти точное правило по [references/REFLECTION-GUIDE.md](references/REFLECTION-GUIDE.md); если убрать — объясните причину.
- [ ] **Шаг 8:** расположите разбор правил по степени влияния на код из [references/KEEP-RULES-IMPACT-HIERARCHY.md](references/KEEP-RULES-IMPACT-HIERARCHY.md).
- [ ] **Шаг 9:** посоветуйте проверить предложенные правки через [UI Automator](https://developer.android.com/training/testing/other-components/ui-automator), уделив внимание пакетам, которых касались правила.

## Обязательные ограничения

- Не меняйте файлы с правилами сохранения.
- Не называйте уровень каждого правила.
- Не создавайте пустой раздел отчёта, если для него нет правил.
- Не упоминайте созданные файлы.
- Не упоминайте сбои во время работы.
- Не рассказывайте о пользе R8.
- Не упоминайте файлы этого навыка.
