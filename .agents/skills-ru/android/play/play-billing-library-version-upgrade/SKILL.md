## Этап 0. Сообщите о намерении

**Что сказать:** до начала сообщите пользователю: «Обновлю Play Billing Library до последней версии».

## Этап 1. Изучите проект и положение дел

1. **Основная проверка — версия сборки:** найдите зависимость оплаты, например `com.android.billingclient:billing`, в `build.gradle`, `build.gradle.kts` или `libs.versions.toml`.
2. **Первичная сборка:** сразу попробуйте синхронизировать и собрать проект.
3. **Запасной путь — фактическая версия:**
   - **Условие:** лишь если сборка сразу не прошла, ищите в исходниках устаревшие API.
   - **Смысл:** наличие устаревшего API показывает **фактическую версию** — последнюю, где этот API ещё был доступен, а не первую версию, где он появился.
   - **Пример:** если есть `SkuDetails`, считайте исходной **PBL v7** или более раннюю, несмотря на строку версии в `build.gradle`.
4. **Цель и путь:** узнайте последнюю стабильную версию через инструмент версий или примечания к выпуску. Рассчитайте прямой или поэтапный путь от фактической версии.

**Как выбрать путь:**

- Если от фактической до целевой версии не больше двух основных версий, переходите напрямую.
- Если больше двух, идите поэтапно с шагом в две основные версии, например v4 → v6 → v8, пока до цели не останется не больше двух версий.
- **Что сказать:** «По коду проект фактически использует PBL [текущая], последняя версия — [целевая]. Планирую [прямой/поэтапный] переход».

## Этап 2. Свяжите документы с планом

Для каждого перехода между основными версиями **обязательно** сведите вместе:

- **[Руководство по переходу](https://developer.android.com/google/play/billing/migrate-gpblv%5BX%5D)**, где `[X]` — целевая основная версия.
- **Примечания к выпуску:** разделы об устаревших и несовместимых изменениях в нужных [примечаниях](references/android/google/play/billing/release-notes.md).
- **Справку для разработчиков** по тем функциям Google Play Billing, которые применяет приложение, например подпискам и разовым товарам.
- **План:** перечислите все нужные правки кода — удалённые API, замены классов и перемены логики — в виде списка проверки.

## Этап 3. Выполните правки

**Что говорить:** перед каждым шагом кратко опишите действие, после него — результат.

### Шаг 1. Согласуйте SDK и среду

- Обновите `build.gradle` под требования SDK, например «PBL 8 требует `compileSdk` 35».
- Проверьте, нужна ли новой библиотеке более свежая версия Android Gradle Plugin (AGP) или Kotlin.

### Шаг 2. Меняйте поведение по смыслу

Разбирайте цель прежнего кода, а не заменяйте строки вслепую.

- **Действие:** выполните все указания об устаревших API и схемы замены из [references/migration-logic.md](references/migration-logic.md), официальных руководств по переходу и общих страниц справки, найденных на этапе 2.
- **Проверка:** убедитесь, что учли все шаги всех документов и пункты списка в справочном файле.

### Шаг 3. Проверяйте после каждого шага, если переход поэтапный

1. Обновитесь до первой промежуточной основной версии.
2. Запустите `./gradlew assembleDebug`, чтобы найти пропущенные несовместимые перемены.
3. Повторяйте до целевой версии.

### Шаг 4. Итоговая проверка

1. Откройте [references/version-checklist.md](references/version-checklist.md) и найдите список по версиям.
2. Для каждой версии между установленной фактической и новой проверьте каждый пункт поиском по файлам либо разбором структуры кода.
3. Запустите модульные тесты и тесты реализации: `./gradlew test`.
4. Убедитесь, что полная чистая сборка проходит: `./gradlew clean assembleDebug`. Затем запустите `./gradlew sync` и `./gradlew build`, чтобы пользователь мог сразу проверить новую версию вручную.

## Итоговый отчёт

Объясните разработчику причины:

- «Обновил SDK до [версия], потому что PBL [версия] требует этого по [причина из справки]».
- «Убрал свою логику `retryConnection()`: библиотека теперь сама восстанавливает связь через `enableAutoServiceReconnection()`».
- «Перешёл с PBL [старая] на [новая] и проверил модульными тестами. С учётом новых функций библиотеки и возможностей приложения советую изучить [новую функцию], например предоплаченные планы или платежи частями: она стала доступна, но ещё не внедрена».
