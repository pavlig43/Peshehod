# Процедурный звук в MiniApp

Создавайте свои описания звука на Kotlin через открытый API MiniApp. Этот навык не охватывает правку цифровой обработки звука, платформенных средств вывода, звукового движка или правил жизненного цикла хоста.

## Что прочитать сначала

1. Прочитайте [public-api.md](references/public-api.md) об описаниях, командах, именах и жизненном цикле.
2. Для музыки прочитайте [music-recipes.md](references/music-recipes.md).
3. Для звуковых эффектов прочитайте [sfx-recipes.md](references/sfx-recipes.md).
4. Перед завершением пройдите [review-checklist.md](references/review-checklist.md).

## Порядок работы

1. Возьмите готовый пресет из `:miniapp:audio-presets`.
2. Меняйте лишь его открытые параметры: имя, начальное число генератора, усиление, плотность и доступные параметры стерео и слоёв.
3. Если одного пресета мало, сочетайте несколько пресетов, дав каждому своё имя.
4. Добавляйте описание звука в код игры, лишь если нужную звуковую роль нельзя выразить готовыми средствами.

Не копируйте Klang, Strudel, коммерческие песни, музыку других игр и сторонние демозаписи. Секвенирование, синтез и фильтры — общие приёмы. Ноты, ритм, аранжировка, начальные числа генераторов и выбор параметров должны быть своими.

## Ход работы

- Храните одну неизменяемую программу в коде игры вне интерфейса.
- Рядом храните константы `AudioControlName` и `SfxName`.
- Передавайте привязанный к сеансу `MiniAppAudio` в компонент или держатель состояния.
- Преобразуйте события игры в вызовы `playMusic`, `stopMusic`, `playSfx` и редкие вызовы `setControl`.
- Проверяйте `AudioCommandResult`; не повторяйте отклонённую команду в цикле.
- Подавление и завершение воспроизведения оставьте хосту: он учитывает видимость, настройки и закрытие сеанса.
- Добавьте общий тест, который компилирует описание звука. Для новых голосов и пресетов делайте воспроизводимый рендер без устройства и проверяйте свойства звука.
- Запустите `allTests` модуля и сборку для Android и iOS.

Для звучания в стиле 8/16-битных игр ограничивайте осцилляторы и огибающие и применяйте `bitCrush`; не снижайте качество выходного формата платформы. Движок выдаёт PCM высокого качества.

Если не хватает открытой возможности для описания звука, укажите конкретный пробел в API и направьте сопровождающего к `docs/superpowers/specs/2026-08-23-kotlin-pattern-audio-design.md` и плану реализации. Не обращайтесь из MiniApp к пакетам `internal`.
